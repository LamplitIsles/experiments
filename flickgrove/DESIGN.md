# FlickGrove interface

FlickGrove is an agent workbench: choose a host/project, open an Orc or Worker, read the conversation, and send or stop work. Desktop keeps a fixed narrow session tree beside a wide detail. Mobile uses the same list followed by a full-screen conversation. Orc roots follow snapshot order; Workers default to collapsed, with indentation and two-line small titles. Root rows show host/project, state, needs-input and current Worker total/working counts. Host, state, model and reasoning effort share a compact metadata row above the editable detail title. The header retains host filtering, quota and Settings; desktop creation uses N and help uses ?. Mobile retains a New session button. Orc, Worker, tree, execution host and conversation navigation item follow CONTEXT.md.

Use project-owned shadcn-svelte components in src/lib/components/ui and Lucide icons. DaisyUI has been removed. Keep a compact Inter-based dark surface, muted borders, blue primary actions and amber for attention states. Use one set of control sizes rather than repeated CSS overrides. Approved context: FlickNote ADR #3180 and spec #3181. Shortcut/completion contracts from #3159/#3160 continue; compact trees replace their spatial presentation.

Interaction uses pointer actions and application shortcuts. N opens creation into project search; I focuses an open Orc composer outside text editing. Up/down locates one visible session and automatically scrolls it into view. Right expands an Orc, then locates its first Worker; left collapses an Orc or locates a Worker’s parent. Enter opens, E toggles Workers. Navigation, selected detail and work state remain distinct. Ordinary pointer controls do not add a global focus marker.

Browser Back, page return/close and Esc share the visible hierarchy. Dismiss the top transient surface before detail; cancel unsaved title/settings edits without submission. A Worker opened from Orc returns to that Orc; a directly opened detail returns to the list. List selections first unwind transient surfaces and replace even nested conversation journeys with one list-returning detail. Restore valid Forward/refresh targets, and resolve closed targets to a parent or list. Keep the root list escapable. Returning retains per-agent drafts, list scroll and expansion and never changes agent lifecycle.

Tab is completion, not page traversal. In / command suggestions and $ skill search it accepts the current item without sending. With no candidate it keeps the input target. Shift+Tab does not introduce another navigation mode. Preserve IME and browser/system combinations. Esc handles the topmost search, dialog or detail once.

Skill search has its own query field, matches names/full descriptions with Organon ranking, and preserves the main draft until selection. Selection inserts the exact invocation at the saved caret; Escape restores the draft/caret. Enter only selects while searching, then sends in Composer; Shift+Enter adds a newline. Keep Send clickable and Stop separate; do not swap them based on draft emptiness.

Render incoming Worker reports as left-aligned, initially collapsed timeline cards, with sender and a short preview. Identify them by delivery source and reportingWorkerId joined to message ID, never by text prefixes. Expand to render full Markdown. Folded state stays in the component; no extra report copy is persisted. Keep delivery errors visible beside the affected operation.

Orc titles edit in place from the detail heading. Enter/checkmark saves, Escape/Cancel cancels only the edit. Keep failed drafts visible and errors actionable; do not create a message or model turn for metadata edits. Codex `thread.name` is authoritative for Orc titles; workspace titles are display caches, updated only after a successful name save and refreshed on startup/read and thread resume. Offline reads retain the cache. Worker headings remain read-only and retain their Orc-assigned task titles.

Worker closure requested by Orc is durable and asynchronous: show Closing on the list item and detail, with the current waiting reason in detail. Keep execution state separate, do not interrupt work, and retain delivery/question/unknown-outcome guards. Pending closure only accepts contextual answers to existing delegated questions. User `/close` remains guarded and explicit.

Use Sonner for brief success feedback, including a three-second tree-close toast. Keep actionable errors beside the relevant operation. Closing detail does not close the tree; Stop interrupts Orc's observed turn, while Workers continue under the existing backend contract.

Verify behavior with the isolated browser fixtures, including desktop and390px mobile, long text, disconnected hosts, settings, question answers, Stop and quota. Tests must never exercise installed credentials or live model sessions. Legacy Penpot boards retain task-flow context; their old DaisyUI styling is superseded by this migration. Use rendered screenshots to assess the current theme.

Weekly quota displays the selected host’s last valid client cache while refreshing, polling every 60 seconds with shared in-flight requests per host. Keep cached values across failure, disconnection, remount and reload; show unknown only without a cache. Preserve supplied reset time/account/source and internal fetchedAt; display reset time only when supplied, and omit update/stale/offline usage copy. Host switching and late responses preserve isolation.

Compact-tree verification uses actual 1440px desktop and 390px Chrome screenshots, including long Worker titles and Settings. There is no matching Penpot board. Browser emulation does not establish real Android/PWA soft-keyboard or iOS gesture behavior.
