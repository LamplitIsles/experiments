# FlickGrove interface

Keep open-session items to a title and one metadata line. Put execution state and needs-input indicators in the upper-right, and Worker counts/disclosure at the lower-right. History results also use two lines; their conversation content belongs in a preview rather than another result row.

N opens the shared host/project selection. Find history then opens an independent title/first-message search, with a compact result list and read-only conversation preview. Back returns from preview to the same search, then to creation. Resume opens the original thread and dismisses the creation journey. Preserve Orc/Worker identity; Workers cannot be promoted. Show writer-lock refusal beside Resume and permit explicit retry, without a force action or automatic mutation replay. Restored transcripts include external continuation in its original order and retain folded Worker report cards for already captured Grove turns, without duplicate user messages across page boundaries.

FlickGrove is an agent workbench: choose a host/project, open an Orc or Worker, read the conversation, and send or stop work. Desktop keeps a fixed narrow session tree beside a wide detail. Mobile uses the same list followed by a full-screen conversation. Orc roots follow snapshot order; Workers default to collapsed, with indentation and two-line small titles. Root rows show host/project, state, needs-input and current Worker total/working counts. Host, state, model and reasoning effort share a compact metadata row above the editable detail title. The header retains host filtering, quota and Settings; desktop creation uses N and help uses ?. Mobile retains a New session button. Orc, Worker, tree, execution host and conversation navigation item follow CONTEXT.md.

Use project-owned shadcn-svelte components in src/lib/components/ui and Lucide icons. DaisyUI has been removed. Keep a compact Inter-based dark surface, muted borders, blue primary actions and amber for attention states. Use one set of control sizes rather than repeated CSS overrides. Approved context: FlickNote ADR #3180 and spec #3181. Shortcut/completion contracts from #3159/#3160 continue; compact trees replace their spatial presentation.

Interaction uses pointer actions and application shortcuts. N opens creation into project search; I focuses an open Orc composer outside text editing. Up/down locates one visible session and automatically scrolls it into view. Right expands an Orc, then locates its first Worker; left collapses an Orc or locates a Worker’s parent. Without detail, Enter opens the navigation item. With detail open, arrow navigation immediately switches it, and the list highlights only the displayed session; no separate navigation outline remains. Enter keeps the displayed session. E toggles Workers. Work state remains separate. Ordinary pointer controls do not add a global focus marker.

Browser Back, page return/close and Esc share the visible hierarchy. Dismiss the top transient surface before detail; cancel unsaved title/settings edits without submission. A Worker opened from Orc returns to that Orc; a directly opened detail returns to the list. List selections first unwind transient surfaces and replace even nested conversation journeys with one list-returning detail. Restore valid Forward/refresh targets, and resolve closed targets to a parent or list. Keep the root list escapable. Returning retains per-agent drafts, list scroll and expansion and never changes agent lifecycle.

Tab is completion, not page traversal. In $ skill search it accepts the current item without sending. With no candidate it keeps the input target. Shift+Tab does not introduce another navigation mode. Preserve IME and browser/system combinations. Esc handles the topmost search, dialog or detail once.

Skill search is a candidate panel attached immediately above Composer with its own query field, matches names/full descriptions with Organon ranking and uses fuzzysort for skipped-character name abbreviations, ranked below exact/keyword/continuous matches, and preserves the main draft until selection. Selection inserts the exact invocation at the saved caret; Escape and browser Back restore the draft/caret. Enter only selects while searching, then sends in Composer; Shift+Enter adds a newline. Keep Send clickable and Stop separate; do not swap them based on draft emptiness.

Render incoming Worker reports as left-aligned, initially collapsed timeline cards, with sender and a short preview. Identify them by delivery source and reportingWorkerId joined to message ID, never by text prefixes. Expand to render full Markdown. Folded state stays in the component; no extra report copy is persisted. Keep delivery errors visible beside the affected operation.

Orc titles edit in place from the detail heading. Enter/checkmark saves, Escape/Cancel cancels only the edit. Keep failed drafts visible and errors actionable; do not create a message or model turn for metadata edits. Codex `thread.name` is authoritative for Orc titles; workspace titles are display caches, updated only after a successful name save and refreshed on startup/read and thread resume. Offline reads retain the cache. Worker headings remain read-only and retain their Orc-assigned task titles.

Worker closure requested by Orc is durable and asynchronous: show Closing on the list item and detail, with the current waiting reason in detail. Keep execution state separate, do not interrupt work, and retain delivery/question/unknown-outcome guards. Pending closure only accepts contextual answers to existing delegated questions. User Close remains guarded and explicit through a dedicated execution-owner call.

Use Sonner for brief success feedback, including a three-second tree-close toast. Keep actionable errors beside the relevant operation. Closing detail does not close the tree; Stop interrupts Orc's observed turn, while Workers continue under the existing backend contract.

Verify behavior with the isolated browser fixtures, including desktop and390px mobile, long text, disconnected hosts, settings, question answers, Stop and quota. Tests must never exercise installed credentials or live model sessions. Legacy Penpot boards retain task-flow context; their old DaisyUI styling is superseded by this migration. Use rendered screenshots to assess the current theme.

Weekly quota displays the page Peer’s last valid client cache while refreshing, polling every 60 seconds with shared in-flight requests per host. Keep cached values across failure, disconnection, remount and reload; show unknown only without a cache. Preserve supplied reset time/account/source and internal fetchedAt; display reset time only when supplied, and omit cache/stale badges, freshness timestamps and background-refresh status copy. Host switching and late responses preserve isolation.

Compact-tree verification uses actual 1440px desktop and 390px Chrome screenshots, including long Worker titles and Settings. There is no matching Penpot board. Browser emulation does not establish real Android/PWA soft-keyboard or iOS gesture behavior.

Direct actions follow spec #3195 and design #3193. Stop remains a button protected by the observed turn ID; slash suggestions, hints and command dispatch are removed. No proactive compact entrance exists. Option/Alt+X targets the current Orc detail, otherwise the navigation Orc; a Worker never closes its parent. Ordinary Composer input accepts this combination without typing a character. Temporary surfaces, title edits and IME block it; other modifier combinations remain untouched.

On mobile, left swipe reveals one Orc row’s Close button; only a subsequent tap executes. Right swipe or an outside tap collapses it. Preserve vertical scrolling, ordinary row navigation and the system back edge. Workers expose no parent-close action. Show refusal beside the initiating row or detail, and keep the three-second success toast and all backend guards. This bounded flow has no extra confirmation, force-close or undo.

The conversation’s lower-right small square Lucide down-arrow button appears only above the bottom. Clicking scrolls to the end and restores existing follow behavior. Incoming content never interrupts reading above the bottom. Keep the overlay inside the transcript, clear of Composer and Worker footer on desktop and mobile; add no scroll library or unread count. Validate skill/swipe/scroll states with isolated 1440px and 390px screenshots; there is no matching Penpot board or claim of pixel fidelity.

Peer architecture follows FlickNote ADR #3283. Every Peer provides the frontend; browsers connect directly to each configured host with independent cache and reconnection. Settings and host configuration belong to the current browser/origin. Creation explicitly captures Orc and Worker execution configuration for the tree. Weekly and model catalogue come only from the page Peer. Remote outage must not disable local operations. Unknown delivery offers receipt lookup and an explicit local dismissal after checking the conversation; dismissal never deletes server history or replays a submission.

Product information follows AGENTS.md: keep implementation and background-maintenance details out of ordinary flows unless they help a user decision or are explicitly requested. Refresh updates the latest successfully retrieved quota; failures retain it without extra cache status labels. Model-list caching follows the same rule.

Message images and question interactions follow spec #3284. Composer supports picker/paste/drop, removable previews, text-plus-images or image-only submission. Limits are 5 images, 5 MiB each, 20 MiB total, 40 megapixels, and 16383px per side; formats are PNG/JPEG/WebP/non-animated GIF. Full dimensions and exact decoded RGBA remain; true lossless WebP is used only if smaller and verified identical. Preview thumbnails are separate, at most 480px/160KB; large images load on demand. Keep upload preparation separate from message acceptance. Image blobs belong to the original Peer/Orc, persist across reload in bounded IndexedDB, and are snapshotted with the operation before clearing Composer. Show actionable storage/preparation/delivery errors and preserve complete recovery alongside newer drafts. Unknown means lookup on the original identity, without replay. Missing native attachments have a readable placeholder.

All questions uses a roughly 600px right drawer, overlay on narrow desktop and full screen on mobile. Display one pending question with enough space for options/descriptions and free text, plus persistent position/Previous/Next and whole-batch Send. Left/Right works throughout the non-editing region; preserve text caret and radio Up/Down. Enter submits one frozen complete batch or selects the first unfilled question. Shift+Enter adds a newline; composition Enter never sends. Repeated Enter cannot submit twice; new arrivals form the next batch. Preserve the existing Option+J/K and Cmd+1–9 question-panel behavior.

Track viewing separately from arrival by Peer-qualified conversation and question ID. Background questions do not switch detail; returning opens unseen new questions without taking Composer focus. Preserve an edited current question. Manual closure persists through ordinary updates/reload, with a new question identity able to reopen. Foreground mobile New/Settings/skill finishes first; Back/Esc and width changes retain the established layer hierarchy. Answered drawer history is directly readable. The one existing question/answer operation appears as one user timeline message tied to its delivery operation and converges on original native/delivery IDs across confirmation and pagination; do not create another send or persisted message copy.

Session directory branches follow spec #3301/design #3295. Put a muted small Lucide GitBranch and at most 12ch of ellipsized branch text in the existing metadata line; title reveals the full value without a new focus target. Preserve row height, upper-right state/input indicators and lower-right Worker disclosure. Workers sharing the Orc directory omit it; different directories show their value even with equal branch names. This is the current working-directory checkout (including worktrees), not a creation-time or tool-local-cd value. Each execution Peer deduplicates directories and polls local Git about every five seconds with bounded, non-overlapping reads, publishing only changes. Non-repo clears the value, detached HEAD uses @shortcommit and query failures/offline retain the last success without placeholders or freshness labels. Closing the last session and shutdown stop reads. Use existing Peer-isolated Chord/cache and verify long branches/Workers at 1440px and 390px; there is no corresponding Penpot design.

Ordinary text/image/question-answer timeline messages express success through their content, without persistent Accepted/success or internal sending/queued status lines. Actual failure keeps the existing localized attention prompt, specific error and recovery action. Unknown retains its necessary unconfirmed/lookup feedback and never becomes failure or automatic replay. Keep durable receipts, Worker report cards and question-panel busy feedback unchanged.
