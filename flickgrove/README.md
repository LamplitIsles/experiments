# FlickGrove

A persistent Orc/Worker workspace shared by desktop and mobile browsers. The **fixed NUC Hub** is the single browser entry; each tree and every Worker stay on their execution host. Closing a browser or conversation leaves execution running. The former ZenCodex TUI has been retired; title generation and the isolated fake app-server now belong to FlickGrove.

From the repository root:

```sh
bun install
bun run --cwd flickgrove build
# NUC: explicit Hub, which also owns its local execution workspace
bun run --cwd flickgrove start --hub --name NUC
# Other host: execution service only, no frontend or PWA
bun run --cwd flickgrove start --name "Neil’s Mac"
```

The default address is **http://127.0.0.1:4318**. Only `--hub` serves the frontend. Each execution machine needs an authenticated `codex` executable and its own active `og` project registry. Choose a host before one of that host's registered projects. Creation opens its Orc with the composer focused. Agents run with full filesystem access and no approval prompts, matching this repository's local Codex policy. Codex configuration is inherited, never rewritten.

## Operator configuration and host registration

Loopback is the default listener. Use explicit `--listen` and `--origin` for an existing Kepos HTTP access path; this application does not provision tunnels, launch SSH processes or configure Kepos. The origin must be an HTTP(S) origin without a path, query or embedded credentials. For example, using already established reachability:

```sh
# Hub: browser-facing advertised origin, with a listener reachable by its proxy
bun run --cwd flickgrove start --hub --name NUC \
  --listen 0.0.0.0 --port 4318 --origin https://grove.example.kepos
# Peer: advertised service origin reachable from the Hub
bun run --cwd flickgrove start --name "Neil’s Mac" \
  --listen 0.0.0.0 --port 4318 --origin https://mac.example.kepos
```

Those domains are examples. Configure the existing proxy to preserve the configured Host and browser Origin. Host validation applies to HTTP and WebSocket upgrades; browser sockets require the Hub's exact Origin. The proxy must forward WebSocket upgrades on `/api/socket` and `/execution/socket`, preserving Authorization for execution peers. Local agent MCP calls use **http://127.0.0.1:PORT**, independently of the advertised origin, and require a separate agent token. Bind to an interface including loopback when using these local MCP calls. The application supplies that local MCP origin and each agent credential in each native thread’s start/resume configuration. It is not a shared process-level credential.

`--state DIRECTORY` selects isolated durable state; the default is `~/.local/share/flickgrove`. `--codex /path/to/codex` selects the executable. `workspace.sqlite` owns local conversations and captured session settings. Private `hosts.json` contains the generated stable instance identity, its access credential and, on Hub, peer credentials and desired defaults. It is written with mode 0600 in a directory created with mode 0700. Protect this directory; do not publish or copy its contents to a browser. The execution service prints the credential **file path**, never the token. Read the peer's `credential` locally as the operator, then supply it in **Settings → Hosts → Add host** with its name and reachable service origin.

Adding a host authenticates `/execution/identity`, checks the execution role and fetches state before saving. Duplicate/self identities, Hub peers, redirects, non-HTTP(S) URLs and identity swaps on address edits are rejected. The masked access-token field is never populated from stored secrets or saved in browser storage. An edit may leave it blank to retain the existing private token. The verified directory is shared across all access devices; names and URLs do not define execution ownership.

Execution peers use `/execution/socket` with `Authorization: Bearer INSTANCE_CREDENTIAL` and `Grove-Host: STABLE_HOST_ID`; `/execution/identity` remains the authenticated registration check. Default mode exposes these and local `/api/mcp/…` only. Browser `/api/socket`, necessary read-only HTTP endpoints and frontend assets belong only to Hub. Chord carries service calls and replicated list/selected-detail state; the replaced SSE and peer polling paths are removed. Agent IDs in the Hub API are qualified by stable host ID; equal host-local IDs cannot collide. Agent tokens never appear in public snapshots or conversations.

## Shared sessions, defaults and outages

Settings store one desired Orc model/effort, one Worker model/effort and one global **Fast** switch on Hub. Fast requires priority-tier support for both selected models. Desired defaults publish to connected execution hosts; Hosts shows pending or failed synchronization. Reconnect checks identity, refreshes authoritative state and resynchronizes defaults. Creation validates the current desired defaults at the selected host and refuses unsupported models, effort or Fast; it never silently downgrades. New Orcs and Workers capture these settings. Existing sessions keep their captured model, effort and service tier. During Hub loss, an execution host and its local MCP tools continue using its last synchronized new-session defaults.

A disconnected host retains its last-known trees and viewed conversations with last-seen information. Its create, send, answer, Stop, close and receipt lookup actions are unavailable. Other hosts remain usable through independent Chord connections. Reconnection verifies identity and starts with a fresh authoritative snapshot. Each browser connection selects its own detail, and the Hub subscribes to the union of those selections on each execution host. A mutation is forwarded once; a lost response produces an unknown outcome. A request timeout closes that transport and uses the existing independent reconnect path; it does not cancel native work. No reconnect queue or automatic mutation replay exists. Reconnect/refresh looks up pending submissions by their original operation ID at their original host; missing records and still-pending operations never trigger a resend. A question answered in another browser appears answered everywhere; concurrent submissions are deduplicated at its execution owner.

The registry, desired defaults, conversations, questions and submitted answers are shared. Host filters, selected conversation, list scroll/expansion, cached weekly quota and unsent drafts belong to each access device, scoped to the Hub origin and host-qualified agent IDs. Desktop keeps a narrow session tree beside a wide conversation. Mobile uses the same expandable Orc/Worker list and full-screen conversation, with usable host/settings forms. Hub loss interrupts unified browser access; surviving execution services keep their trees. There is no tree replication, takeover or leader election.

Stop the backend with Ctrl+C. On restart, active local sessions appear interrupted; the next explicit message resumes their durable thread. Confirmed messages, questions, answers, ownership and captured models survive restart. Remote Hub display caches are in memory only, refreshed from their owner after startup.

## Native runtime ownership

Each execution host lazily starts **one Grove-owned managed Codex app-server** for all of its Orc/Worker handles, history/model/skill/usage catalog reads and title threads. Concurrent opens share the same connecting client. Grove uses the existing explicit executable path, environment and bootstrap; it does not attach to, start or manage a system daemon.

Thread start/resume carries each agent’s cwd, role instructions, model/effort/service tier and private MCP token. Native notifications are filtered by thread ID. Native synchronous requests without an owned thread are rejected; Grove’s async question/MCP flow remains the supported interaction and no approval/tool consumption is fabricated. Stop targets only its observed thread/turn. Closing an agent aborts its title task and unsubscribes only its native thread, leaving Codex’s native unload lifecycle and other threads intact. Tree/report/question closure guards and native writer locks remain in force.

A shared process disconnect affects its open agents together. They show interrupted/unknown results; the next explicit operation reconnects the managed client and resumes the original thread. Unknown submitted inputs are not replayed. Closing a browser releases only observation. Shutting down Grove closes its managed client. Isolated tests observe one process for two concurrent agents plus catalog/title work, versus the previous per-agent processes and separate catalog process. This is process-count evidence; no measured memory or CPU saving is claimed.

## Conversation controls and usage

Press **N**, choose an execution host and one of its registered projects, then select **Find history** to search that directory's Codex sessions by title or first message. The list includes CLI sessions and archived or Grove-closed sessions. Search uses Codex's SQLite-backed metadata through app-server `thread/list`; Grove does not open the database directly or build a second search index. Indexed metadata is paginated across projects and filtered on the execution host by filesystem directory identity, so casing and symlink aliases can match without merging distinct directories on case-sensitive filesystems. Preview reads paginated conversation items without copying them into Grove's database. Restoring a closed Orc refreshes its history boundary, so CLI continuation during closure is visible too. Captured Grove turns replace their native history counterparts by turn identity to preserve Worker report cards; pagination deduplicates those captured groups. Only the boundary and captured-message count are added to workspace metadata, not another history-message copy.

Resume continues the original thread without sending a message. CLI sessions become Orcs with their existing model, reasoning effort and service tier; closed Grove Orcs retain their identity and keep old Workers closed. Workers remain read-only and link to their owning Orc. Already open sessions open their existing detail. Codex's writer lock rejects sessions held by another instance; the preview shows the error and permits explicit retry after that instance releases it. Grove never removes locks or forces ownership. The execution host must run a Codex app-server supporting indexed `thread/list`, paginated items and writer locks.

Open-session rows and history results use two compact lines. Execution state and input needs sit at the upper-right, while Worker disclosure and counts share the metadata line. They do not consume separate rows.

Send ordinary instructions to Orc. An idle Orc uses native `turnStart`; new input during execution uses `turnSteer` immediately in submission order, without waiting for the model’s answer. Each submission has its own stable operation ID, separate from a socket request ID and native turn ID. The browser persists each operation in its own origin/agent-scoped record before invocation, so another tab cannot erase pending content or identity. It echoes it immediately and clears the submitted draft so editing and further sends remain available. Sending stays disabled while offline or Stopping, while an offline draft remains editable.

An accepted receipt proves native input acceptance, not model consumption or completed work. Success adds no toast. A rejected user message can be restored alongside a newer draft for an explicit new submission. Unknown messages retain their text and **Check receipt** action; lookup reads saved owner-side evidence and never calls a model. Native acceptance followed by a crash before saving its result remains unknown. A late error cannot erase an already observed submission. Failed Worker reports retain an explicit Retry action with their original report identity; unknown reports keep their existing closure guard.

`$` opens the candidate panel directly above Composer, with an independent search field over the owning host's project. Search matches skill names and full descriptions with Organon-style ranking, plus fuzzysort name-only abbreviation matching (for example, `grdo` finds `grill-with-docs`); Tab or Enter inserts the selected name at the saved cursor position without sending. Up/down selects a candidate; Escape or browser Back cancels and restores the draft and caret. Models and effort are settings, not skill arguments. Session titles are generated from the first message in a separate lightweight-model thread. This application does not create, merge or deploy PRs itself.

Click an Orc title in its detail panel to edit it. Enter or the checkmark saves; Escape or Cancel discards the edit. The owning execution host saves the canonical Codex thread name through `thread/name/set`, then updates its workspace display cache, including remote hosts. Failed saves retain the old title. Backend startup reads Orc names without resuming turns; explicit thread resume refreshes them again. Unreachable Codex reads retain the last cached title. Changing a title sends no model message. Worker titles remain managed by Orc.

Workers are read-only in the browser. Orc can start, list, read, instruct and close only its own Workers through the host-local `flickgrove` MCP server. Workers report only to their parent. Orc and Worker sessions enable native multi-agent tools for independent review. Reviewer selection belongs to the applicable skills and agent configuration; Grove does not maintain a reviewer allowlist. Role instructions restrict native spawning to review; implementation delegation stays with FlickGrove Workers. The spawning session manages its native reviewers, which are not displayed as Workers in the Grove tree. This restriction is instruction-based, not enforced by the tool runtime. Worker async questions route to Orc; contextual replies resolve only explicit question IDs.

`worker_close` records a durable closure request. A ready Worker closes after native thread release succeeds; a running Worker completes its current turn without interruption and closes automatically once its reports are delivered and delegated questions are answered. Pending Workers show Closing and a waiting reason and reject new tasks; explicit answers to existing questions remain allowed. Failed terminal turns also permit closure. Restart or disconnection retains the request with an unknown outcome; Orc can inspect it and explicitly use `confirmInterrupted` to acknowledge the interruption, while report and question guards still apply. The user’s direct Close action retains the existing tree guards. Orcs and Workers stay visible with their handles until native unsubscribe succeeds. A failed release keeps them retryable: retry direct Close for Orc, or `worker_close` for Worker; automatic Worker release failure shows its reason and waits for an explicit retry. History restore waits for in-flight Close and reuses an agent whose failed release kept it open.

Incoming Worker reports appear on the left of the conversation timeline as folded cards. Expand a card to read its full Markdown; ordinary user messages remain separate. This uses existing delivery source and reporting Worker IDs and adds no report storage.

Questions appear complete while execution may continue. Selecting an option does not submit it. Left/right changes questions only when the navigation group has focus. **Send answer** confirms one answer and advances to the next unanswered question. Question and composer drafts survive refresh; IME and text editing retain precedence over application shortcuts.

There are no slash actions or proactive compact controls. A Working Orc has a prominent Stop button and a composer stop square. Stop calls official SDK interruption for the **observed current Orc turn ID**; it never stops Workers. Stopping stays pending until an authoritative completion arrives. Confirmed user interruption returns Idle and shows feedback; a normally completed turn shows its actual outcome. Unknown acceptance stays unknown, never becomes success on a timer and never stops a later turn through replay. Reports, questions and uncertain deliveries remain available and retain close guards. A report received while Stopping is retained for explicit retry after the turn outcome.

**Option+X** on Mac or **Alt+X** elsewhere closes the current Orc tree: an open Orc detail takes precedence, otherwise the unique navigation Orc is the target. A Worker never implicitly closes its parent. The shortcut also works in ordinary Composer input, blocks character insertion, and pauses during temporary surfaces, title editing or IME. On mobile, swipe an Orc row left to reveal **Close this tree**, then tap to execute. Only one row exposes the action; swipe right or tap outside to collapse it. Vertical scrolling and ordinary row taps remain available, and Workers have no tree-close action. Close uses a dedicated Chord `closeTree` call through Hub and its execution owner, without sending a user message. Ask Orc to close its Workers first. Closure requires an idle Orc, no open Workers, no unanswered questions, no undelivered reports and no unconfirmed delivery. Success removes the tree and shows a three-second toast; refusal explains the guard beside the row or current detail. **Zero Workers is only a current count**; the application does not infer task completion or suggest closing from it.

The upper-right weekly ring shows **remaining account quota**, for the selected tree's host account or Hub's account when nothing is selected. The host catalog reads official account rate limits and chooses the window with `windowDurationMins: 10080`, regardless of primary/secondary position. Remaining is clamped `100 - usedPercent`; without a valid host cache, missing data is a dash, never invented zero. Hosts and model quota buckets are never summed. Cyan is normal; amber means 20% or less. The popover shows account identity when supplied, source host and supplied reset time. Each host has an origin-scoped client cache of its last valid percentage and supplied account/source/reset metadata. Selection displays that host’s cache immediately and refreshes in the background; component remounts and page refreshes retain it. Requests poll every 60 seconds and manual refresh remains available; overlapping requests to the same host are shared. Failures, disconnection and missing numeric values retain the last valid value; only a host without a cache shows a dash. Late responses cannot replace the current host. Reset time appears only when the source supplies it; update times and stale/offline usage messages are omitted.

## Browser and development

Shortcuts: up/down moves the unique navigation item through visible sessions and scrolls it into view; right expands an Orc or enters its first Worker; left collapses an Orc or locates a Worker’s parent. With detail open, arrow navigation switches the detail immediately and highlights only that session; without detail, Enter opens the navigation item. E toggles Workers, N opens creation with project-search focus, I focuses the Orc composer, Escape dismisses the top visible layer, and ? shows help. Text editing, IME, browser/system combinations, skill search and question navigation take precedence. Tab completes the current `$` candidate and keeps the input target; Enter sends, Shift+Enter inserts a newline. Send remains clickable and Stop has its own control while Orc is working. Tree closure produces a three-second toast.

Browser Back, page return/close and Esc unwind the same visible layers: a dialog, skill search, quota popover, title edit or host filter closes before its underlying conversation. A Worker opened from an Orc returns to that Orc; a detail opened directly from the list returns to the list. List switching first dismisses active transient layers, then replaces the entire conversation journey with one detail that returns to the list, including switches from a nested Worker. Forward restores valid targets; refresh restores detail with a list return target. Closed targets resolve to a valid parent or list. The root list allows normal browser departure. Returning preserves drafts, scroll and expansion and does not send, Stop or Close an agent.

A small Lucide **Jump to bottom** button appears at the lower-right of the Orc/Worker conversation when reading above the bottom. Clicking scrolls to the end and restores automatic following. Reading above the bottom pauses following; short conversations and the bottom hide the button. It stays within the transcript, above Composer or the Worker footer.

Chrome notification permission is requested at first pointer interaction. Notifications cover idle transitions, errors and new questions while the page is open, suppress replay after reconnect, and open the corresponding Orc. Install the PWA through Chrome or the progressive install action. Its service worker caches the built shell/fonts, never API responses. Offline reload restores cached conversations and drafts with sending disabled. Secrets are not browser-cached.

For development, start the backend **with `--hub`**, then run `bun run --cwd flickgrove dev`. The Vite API proxy targets port 4318; development does not install a service worker.

bun run test
bun run typecheck

## UI foundation

Desktop session creation uses N; ? opens shortcut help. Hosts management lives in Settings. A fixed narrow session list stays usable beside the detail, whose metadata sits above the editable title. Orc roots retain snapshot order and show host/project, work state, input needs and current total/working Worker counts. Workers default to collapsed and use indented, small titles clamped to two lines. With detail open, its session is the only highlighted row. Without detail, a single keyboard navigation marker locates the item to open. Execution state remains separate. Mobile retains a New session button.

The frontend uses project-owned shadcn-svelte components (Bits UI), Lucide icons and a compact dark workbench theme. Read [DESIGN.md](DESIGN.md) before changing the component layer. Ordinary buttons do not retain visible focus rings after pointer actions. No compact-tree Penpot board exists; screenshots assess rendered usability. Browser checks use 1440px and 390px Chrome; real Android/PWA soft keyboards and iOS back gestures need device acceptance.
