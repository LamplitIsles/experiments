# FlickGrove

A persistent Orc/Worker/Reviewer/Researcher workspace with symmetric Peers. Every Peer serves the same frontend and owns its local session trees. Open any reachable Peer, then configure additional hosts in that browser. The browser connects directly to each Peer; the page host does not relay remote business calls. Closing a browser leaves execution running.

```sh
bun install
bun run --cwd flickgrove build
bun run --cwd flickgrove start --name "Neil’s Mac"
# The same command runs a Peer on NUC; there is no --hub role.
bun run --cwd flickgrove start --name NUC
```

The default address is **http://127.0.0.1:4318**. Each execution machine needs an authenticated `codex` executable and its own `og` project registry. Orc, Worker and Researcher threads use the full-access local Codex policy; Reviewer threads use the native read-only sandbox. Fixed role instructions keep all implementation and repairs with Workers and prohibit Reviewer verification. These instructions express responsibility and do not guarantee tool isolation. Grove never rewrites the user's Codex configuration.

## Managed workflows, Reviewers and Researchers

Spec **#3573**, originating discussion **#3540**, adds managed review to existing Peer, Workspace, MCP and Chord lifecycle. Orc coordinates, investigates and discusses; all code development and repairs go to the sole implementation Worker for each repository/spec/PR, with no small-fix exception. Reviewers read actual code, the fixed diff, full FlickNote spec, standards and existing logs/screenshots; they do not run tests, builds or browsers. Missing verification goes back to the original Worker. There is no ticket requirement: the default workflow is settled discussion → self-reviewed spec → one Worker; existing tickets are read and new tickets are created only on explicit request.

Each execution Peer initializes `~/.config/flickgrove/config.toml` and adjacent `prompts/` from versioned repository templates before serving. `--config PATH` selects an explicit configuration path. Initialization creates only missing files, retries partial initialization and adds newly shipped prompt files; existing customization is never overwritten. Invalid/missing Orc prompt or Reviewer profiles, unavailable model/effort and unreadable/empty explicit prompts fail clearly. Relative prompt paths resolve against the configuration directory. Profile changes affect subsequent newly created Reviewers; existing sessions and re-review retain captured prompt/model/effort snapshots in workspace state. There is no UI configuration or live prompt reload.

```toml
[reviewers.standards]
model = "gpt-6-luna"
reasoning_effort = "high"
prompt_file = "prompts/standards.md"
```

Spec **#3596** adds a distinct owned Researcher. Orc-only `researcher_start/list/read/send/close` delegates one exact question with a registered project, title and bounded message/context; Researcher-only `researcher_report` validates that question and returns natural-language evidence asynchronously to its owner. Worker/Reviewer tools cannot address Researchers, and cross-owner access is refused. No review target, spec, fixed-point, HEAD or PR requirement applies. Follow up the same Researcher to retain context. Reports carry Researcher identity and question; async questions route through Orc and explicit question IDs. Closing/retry/restart use the existing real native-release and delivery guards, without automatic replay. History continues through its owning Orc.

`[researcher]` requires `model`, `reasoning_effort` and `prompt_file`, with the same validation and relative-path rules as Reviewer profiles. Defaults use the established researcher role's gpt-6-luna/high and `prompts/researcher.md`. Startup adds only a missing Researcher table and missing default prompt to an existing Peer configuration, preserving existing tables, comments and customized prompt text. An existing Researcher table is validated, never repaired or overwritten. New Researchers privately capture prompt text/model/effort; restore retains that snapshot and the original native thread. No separate configuration UI or native database migration is introduced.

`grove-research` investigates directly by default. Parallel delegation requires 2–4 independent, decision-relevant questions, each with distinct evidence scope; source-type splits of one question and one-Researcher gap follow-ups do not qualify. Researchers gather verified facts/sources, interpretations, conflicts, unknowns and leads. They do not develop code, write repository/FlickNote state, create agents or choose the final recommendation. Orc synthesizes and archives through FlickNote MCP. These write constraints express duties, not hard permissions; normal investigation and network tools stay available.

Every Grove thread start and original-thread resume overrides `agents.enabled=false`, `features.multi_agent=false` and `features.multi_agent_v2=false`. The supported `agents.enabled` override is necessary because a model may select V2 even with false feature flags. Official Codex 0.160.0 source resolves this override before saved history/model selection and registers no collaboration tools for Disabled. Grove keeps its own MCP, extra skill roots and shared app-server; global CLI configuration and unrelated CLI threads are unchanged. Evidence covers strict wire for all four roles plus installed-native metadata/discovery, not a paid model turn or native tool inventory (no metadata-only inventory endpoint is available). Source references: [configuration/model precedence](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/config/mod.rs), [resume precedence](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/session/mod.rs), [tool registration](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/tools/spec_plan.rs).

The `[orc]` section requires `prompt_file = "prompts/orc.md"`. Initialization creates this prompt only when absent, alongside the Reviewer files. New Orcs capture its text; original-session restoration retains the saved text. A prefeature Orc without a snapshot captures it once on explicit restoration (history continuation or message resume), without a migration. Config changes affect new Orcs; there is no Orc model configuration or prompt hot reload. Configurable duties compose with mandatory Grove role/communication/lifecycle rules, which take precedence.

All four Reviewer sections are required: `standards`, `spec`, `high_risk_spec`, and `penpot`. Shipped defaults were verified against the current native named reviewer configuration: Standards/normal Spec use gpt-6-luna/high; high-risk Spec/Penpot use gpt-6.1-sol/high. Editable axis prompts combine with fixed Grove responsibility, communication and lifecycle instructions. Orc instructions are supplied through native `developerInstructions` at creation and restoration. Native initial-context/compact machinery maintains those instructions; Grove does not add reminder messages after compaction. Loaded native threads retain their already loaded context rather than promising prompt reload.

Orc MCP exposes `reviewer_start`, `reviewer_list`, `reviewer_read`, `reviewer_send`, and `reviewer_close`; Reviewers expose only `reviewer_report`. Start takes registered `project`, `profile`, `title`, `spec`, `fixedPoint`, `reviewedHead`, and initial `message`. Send explicitly supplies spec/fixed point/HEAD and repair scope, continuing the same Reviewer; optional `questionIds` resolve only the named delegated questions. Reports preserve natural language, Reviewer identity and target; their `spec`, `fixedPoint` and `reviewedHead` must match the current assignment. An older PASS stays attached to its old HEAD. Standards and Spec remain independent, with high-risk routing and conditional Penpot. List/read after unknown start/send admission; never blindly replay. An unconfirmed native startup remains visible for inspection, and cannot accept another start through send.

Reviewers appear as distinct child rows with read-only detail, target and model/effort; users send instructions and answer questions through the owner Orc. Reports use the existing folded timeline cards with a Reviewer label and original-agent file previews. Questions forward to Orc. Closure reuses the Worker delivery/question/native-release guards, including durable Closing, explicit interrupted-turn confirmation, native failure retry and no interruption of unrelated threads. Close all Workers, Reviewers and Researchers before tree closure. Restart retains role/owner/target/config/report snapshots, marks interrupted work explicitly, and never automatically dispatches tasks. Tree Fast applies to editable open members and future owned agents under each model's capability; Reviewer and Researcher model/effort remain snapshot-owned.

The repository ships only the workflow skills and their referenced resources under `skills/`, with unique `grove-` invocation names. Grove registers this version-owned root using native `skills/extraRoots/set` once per Grove-owned app-server connection, so discovery applies across registered projects and both creation/restoration. Updates use the shipped files directly, rather than freezing an initial copy in Codex home. Global same-name skills and configuration stay untouched. Native support is required; registration failure is explicit.

Orc Composer shows Plus for direct image selection, then Lucide icon+English **Discuss**, **Implement**, **Review**, **Re-review**, then **Research** (Telescope). These insert `$grove-grill-with-docs`, `$grove-to-orc-impl`, `$grove-code-review`, `$grove-review-again`, and `$grove-research` at the current selection with whitespace where needed. Drafts/images/caret and IME remain intact; insertion focuses Composer and never sends. Mobile keeps one compact horizontally scrollable controls row and the other-skill icon; Option/Alt+S still searches other skills. Controls respect connection and pending/disabled state.

Isolated real Peer/Chord, strict native wire, stdio MCP and installed-native discovery tests use only temporary state and configuration. Actual 1440px/390px browser screenshots are in `.scratch/flickgrove-managed-reviewers/screenshots/` and `.scratch/flickgrove-managed-researchers/screenshots/`. No service deployment, credentials, paid model turn or live registry mutation is part of verification; provider-driven compaction and real-device keyboard behavior remain outside these isolated checks.

## Connections and browser preferences

Use `--listen`, `--port` and `--origin` for an existing HTTP(S) proxy/tunnel. This application does not provision tunnels. The configured origin has no path, query or embedded credentials. Proxies preserve Host and WebSocket upgrades on `/api/socket`, including `Sec-WebSocket-Protocol`. Local agent MCP calls use `http://127.0.0.1:PORT` and separate per-agent tokens, independently of the advertised browser origin.

`--state DIRECTORY` selects durable state (default `~/.local/share/flickgrove`); `--codex PATH` selects the executable. `workspace.sqlite` owns conversations and each tree's captured execution settings. Private mode-0600 `hosts.json` stores only the stable Peer identity and access credential. Read the remote credential locally and enter it under **Settings → Hosts → Add host**. The browser stores host addresses and credentials in origin-scoped local storage; another browser, device or page origin has independent configuration. There is no configuration synchronization or backend host directory.

Registration opens a direct WebSocket, authenticates and checks stable identity before saving. Self/duplicate identities and identity swaps on address edits are rejected. An edit may leave the masked token field blank to keep its browser-stored token. Addresses must be reachable from the accessing device: `localhost` refers to that device, not the machine providing the page. A secure page also requires browser-compatible secure remote endpoints.

Same-origin browser sockets use the page Origin. Cross-origin sockets authenticate using the `grove.v1` and `grove-auth.CREDENTIAL` subprotocols; credentials do not appear in request URLs. No workspace state or execution operation is exposed over unauthenticated HTTP. Chord carries calls and replicated local list/selected-detail state. Peer-qualified session IDs prevent collisions; agent MCP tokens never appear in public state.

Settings save this browser's **new-session preferences**: Orc/Worker model and effort, Fast, and selected execution host. Creating a session explicitly sends settings to that Peer, which validates capability without silently downgrading. The tree captures both Orc and Worker execution settings; future Workers use their Orc's captured configuration, including after restart. Later browser preference changes cannot modify existing trees. There is no global settings push between Peers.

The opened Orc or Worker has an individual **Session settings** control for Model and Reasoning effort with atomic Save/Cancel (**Option/Alt+M**). A separate **Tree Fast** Zap control (**Option/Alt+F**) targets the owning Orc and all open editable Workers, Reviewers and Researchers, and sets the Fast policy for future Workers. The Orc list indicator shows this desired tree policy. Unsupported models stay on their original model at standard speed; the control tooltip explains capability and the confirmed next-turn tier. Model/effort changes affect only the selected agent and recompute its tier from the tree policy. Physical-key shortcuts preserve Composer drafts/selection; IME, title editing and foreground panels block them.

Changes use native `thread/settings/update` on original shared app-server threads. Each member's confirmed settings remain authoritative; multi-thread updates are not atomic. Explicit tree mutations persist desired policy within the owning tree; other trees, model/effort defaults and browser new-session preferences remain independent. Changes affect subsequent new turns; current work and `turn/steer` retain their configuration. Partial failure or unknown outcomes remain actionable beside the control. Explicit Retry first reads native settings before any necessary update; no automatic replay, rollback, new process, message or turn occurs. One in-flight tree action excludes concurrent starts, model saves and closure. Existing tree policy derives from the owner's current setting until explicitly changed.

First opening a known agent immediately displays its target identity and stable Composer, while only the transcript loads. Draft typing is available; Send, Stop, title and settings mutations wait for authoritative detail. Arrival preserves Composer focus, caret and draft. Failure retains the frame with localized Retry. Cached history and reading positions retain their existing bounded browser-memory contract.

## Independent connections and recovery

Each browser-to-Peer connection independently reconnects and retains its last-known read-only cache. Remote failure disables only that Peer's writes; reachable Peers remain usable. Standard WebSocket Ping/Pong on each server checks the browser connection. The browser also uses a lightweight identity probe to detect a stalled path because browser WebSocket has no Ping API. Business request deadlines reject individual requests without closing the socket. No quota or model query acts as a heartbeat.

Reconnection verifies identity and obtains a fresh authoritative snapshot. Each browser/connection independently selects its visible detail. Closing an observation connection does not interrupt execution.

Each message has an immutable operation ID and content envelope. Public receipts are **accepted** (the existing native start/steer confirmation) or **rejected** (definitely not received). Lookup on the owning Peer returns `null` when still processing, native admission is unknown or no record exists. Null supplies no rejection, recovery permission or replay. Browser-local results are **pending / accepted / rejected**; the existing single operation journal and backend execution states keep their internal encoding, without storage migration or a second decoder.

## Native runtime ownership

Each execution host lazily starts **one Grove-owned managed Codex app-server** for all of its Orc/Worker handles, history/model/skill/usage catalog reads and title threads. Concurrent opens share the same connecting client. Grove uses the existing explicit executable path, environment and bootstrap; it does not attach to, start or manage a system daemon.

Thread start captures each agent’s model/effort/service tier alongside cwd, role instructions and private MCP token. Resume keeps the native thread’s saved model/effort/service tier; Grove reconciles its display cache at startup and when selecting detail. Native notifications are filtered by thread ID. Native synchronous requests without an owned thread are rejected; Grove’s async question/MCP flow remains the supported interaction and no approval/tool consumption is fabricated. Stop targets only its observed thread/turn. Closing an agent aborts its title task and unsubscribes only its native thread, leaving Codex’s native unload lifecycle and other threads intact. Tree/report/question closure guards and native writer locks remain in force.

A shared process disconnect affects its open agents together. They show interrupted/unknown results; the next explicit operation reconnects the managed client and resumes the original thread. Unknown submitted inputs are not replayed. Closing a browser releases only observation. Shutting down Grove closes its managed client. Isolated tests observe one process for two concurrent agents plus catalog/title work, versus the previous per-agent processes and separate catalog process. This is process-count evidence; no measured memory or CPU saving is claimed.

## Conversation controls and usage

Press **N**, choose an execution host and one of its registered projects, then select **Find history** to search that directory's Codex sessions by title or first message. The list includes CLI sessions and archived or Grove-closed sessions. Search uses Codex's SQLite-backed metadata through app-server `thread/list`; Grove does not open the database directly or build a second search index. Indexed metadata is paginated across projects and filtered on the execution host by filesystem directory identity, so casing and symlink aliases can match without merging distinct directories on case-sensitive filesystems. Preview reads paginated conversation items without copying them into Grove's database. Restoring a closed Orc refreshes its history boundary, so CLI continuation during closure is visible too. Captured Grove turns replace their native history counterparts by turn identity to preserve Worker report cards; pagination deduplicates those captured groups. Only the boundary and captured-message count are added to workspace metadata, not another history-message copy. Loaded native transcript pages and their next cursor survive detail switches in a browser-memory LRU keyed by Peer-qualified agent ID and history boundary (at most 12 conversations and 8 MiB of serialized UTF-16 history). Cached revisits restore content and reading position before the first target paint; current Grove messages continue through the existing detail subscription. Over-limit history remains readable in its current detail but may need loading again after leaving. Closure/removal or a changed boundary invalidates the entry and ignores late reads. Failed earlier-page reads retain loaded content and cursor for explicit Retry; offline returns retain available pages. No native history messages or DOM are persisted, and refresh starts a new cache.

Conversation messages show compact local times, with short dates on previous days and full date/time plus timezone on hover. Native history uses recorded item lifecycle millisecond timestamps when available; missing times are omitted. User messages prefer item start time and assistant messages prefer completion time. Grove-captured messages retain their stored admission/completion times; pending submissions use their browser submission time until confirmed by the original Peer.

Resume continues the original thread without sending a message. CLI sessions become Orcs with their existing model, reasoning effort and service tier; closed Grove Orcs retain their identity and keep old Workers closed. Workers remain read-only and link to their owning Orc. Already open sessions open their existing detail. Codex's writer lock rejects sessions held by another instance; the preview shows the error and permits explicit retry after that instance releases it. Grove never removes locks or forces ownership. The execution host must run a Codex app-server supporting indexed `thread/list`, paginated items and writer locks.

Open-session rows and history results use two compact lines. Execution state and input needs sit at the upper-right, while Worker disclosure and counts share the metadata line. They do not consume separate rows. The open-session metadata line includes a muted Lucide GitBranch indicator, with branch text capped at 12ch, ellipsis and the complete value in its title. It shows the current checkout of the session’s registered working directory, including a worktree’s own branch; it does not track tool-local `cd` or freeze the branch at creation. Workers sharing their Orc’s directory omit the duplicate indicator; a different directory shows its own value even when branch names match.

Each execution Peer deduplicates open-session directories (including symlink aliases), reads local Git metadata promptly on startup/new directories and polls about every five seconds after a completed cycle. At most two reads run concurrently, each Git subprocess has a 1.5-second limit, and no network Git operation runs. Only changed values publish through the existing Chord snapshot/detail and Peer-specific browser cache. Non-repositories show nothing and explicitly clear an earlier value; detached HEAD shows `@` plus a short commit, and unborn branches show their name. Query failures and offline Peers retain the last successful value, with no unknown placeholder or freshness label. Closing the last session stops its directory’s reads; shutdown aborts queries and discards late results. Branch state stays in Peer memory, without a database copy, and is reread on Peer startup.

Send ordinary instructions to Orc. An idle Orc uses native `turnStart`; new input during execution uses `turnSteer` immediately in submission order, without waiting for the model’s answer. Each submission has its own stable operation ID, separate from a socket request ID and native turn ID. The browser persists each operation in its own origin/agent-scoped record before invocation, so another tab cannot erase pending content or identity. It echoes it immediately and clears the submitted draft so editing and further sends remain available. Sending stays disabled while offline or Stopping, while an offline draft remains editable.

An accepted receipt proves native input acceptance, not model consumption or completed work. Pending text, image and question-answer messages show the compact **Sending…** feedback; accepted messages display their normal content without a success label or toast. Rejected messages retain the attention prompt, specific reason and recovery action. Publication and reconnection reconcile pending identities with lookup, without receipt polling, a separate uncertain panel or automatic resubmission. A rejected user message can be restored alongside a newer draft for an explicit new submission. Native acceptance followed by a crash before saving its result remains pending. An observed message or accepted receipt cannot be reversed by null, an older publication or a late error. Failed Worker reports retain explicit Retry with their original report identity; unresolved reports keep their existing delivery feedback and closure guard.

`$` opens the candidate panel directly above Composer, with an independent search field over the owning host's project. Search matches skill names and full descriptions with Organon-style ranking, plus fuzzysort name-only abbreviation matching (for example, `grdo` finds `grill-with-docs`); Tab or Enter inserts the selected name at the saved cursor position without sending. Up/down selects a candidate; Escape or browser Back cancels and restores the draft and caret. Models and effort are settings, not skill arguments. Session titles are generated from the first message in a separate lightweight-model thread. This application does not create, merge or deploy PRs itself.

Click an Orc title in its detail panel to edit it. Enter or the checkmark saves; Escape or Cancel discards the edit. The owning execution host saves the canonical Codex thread name through `thread/name/set`, then updates its workspace display cache, including remote hosts. Failed saves retain the old title. Backend startup reads Orc names without resuming turns; explicit thread resume refreshes them again. Unreachable Codex reads retain the last cached title. Changing a title sends no model message. Worker, Reviewer and Researcher titles remain managed by Orc. History labels all owned roles and directs continuation through View owning Orc, with role-specific help; it never offers them rejected Orc resume actions.

Workers are read-only in the browser. Orc can start, list, read, instruct and close only its own Workers through the host-local `flickgrove` MCP server. Workers report only to their parent. Independent review uses Grove Reviewers, each with a separate native thread, owning Orc and saved review target. Native collaboration tools are disabled on Grove-managed threads. Worker async questions route to Orc; contextual replies resolve only explicit question IDs.

`worker_close` records a durable closure request. A ready Worker closes after native thread release succeeds; a running Worker completes its current turn without interruption and closes automatically once its reports are delivered and delegated questions are answered. Pending Workers show Closing and a waiting reason and reject new tasks; explicit answers to existing questions remain allowed. Failed terminal turns also permit closure. Restart or disconnection retains the request with an unknown outcome; Orc can inspect it and explicitly use `confirmInterrupted` to acknowledge the interruption, while report and question guards still apply. The user’s direct Close action retains the existing tree guards. Orcs and Workers stay visible with their handles until native unsubscribe succeeds. A failed release keeps them retryable: retry direct Close for Orc, or `worker_close` for Worker; automatic Worker release failure shows its reason and waits for an explicit retry. History restore waits for in-flight Close and reuses an agent whose failed release kept it open.

Incoming Worker reports appear on the left of the conversation timeline as folded cards. Expand a card to read its full Markdown; ordinary user messages remain separate. This uses existing delivery source and reporting Worker IDs and adds no report storage.

Chat Markdown, historical conversations and expanded Worker reports render math with the existing SvelteMarkdown `markedKatex` extension and KaTeX. Use `$...$` or `\(...\)` inline and `$$...$$` or `\[...\]` for display math. Code and ordinary currency stay literal; unfinished or invalid expressions stay readable. Math cannot enable trusted HTML or links. Fonts and CSS are bundled locally, and long formulas scroll within the message. Generated-file Markdown previews retain their separate rendering behavior.

Fenced `mermaid` diagrams load on demand in the shared chat renderer, use strict read-only rendering and the dark theme, and show their source if rendering fails. Long diagrams scroll inside the message. Ordinary fenced code uses TanStack Highlight through the SvelteMarkdown adapter, with one shared highlighter for JavaScript/TypeScript/JSX/TSX, JSON, HTML, CSS, Python, shell, SQL, YAML and Svelte. Unknown or missing languages remain escaped plaintext; long code scrolls locally. These additions also apply to history and expanded Worker reports.

**All questions** opens a wide right drawer (about 600px on desktop, overlay on narrow desktop, full screen on mobile). One pending question is shown at a time, with persistent question position and Previous/Next controls. Left/Right switches questions anywhere in the non-editing question region; text caret arrows and radio Up/Down retain their normal meaning. Selection and answer drafts survive switching and reload. Option+J/K and Cmd+1–9 keep their existing question-panel behavior.

**Send all answers** or Enter freezes every currently pending question and answer into one immutable operation and one native start/steer. A missing answer selects the first unfilled question instead of sending. Shift+Enter inserts a newline; IME Enter only confirms composition. Repeated Enter during submission does not duplicate the batch. Questions arriving during submission belong to the next batch. Rejected batches retain the complete envelope for explicit **Retry**, revalidating all original questions. Unconfirmed outcomes remain pending and are reconciled automatically on the original identity, without replay; only native confirmation marks the original questions answered. The same question-and-answer batch appears immediately as one user message with its actual delivery status; confirmation, reload and pagination converge on that original identity. Answered questions remain directly readable in the drawer, without a second history fold.

Background questions never switch the conversation. Returning to a session with unseen new question IDs opens its drawer without moving Composer focus. A current edited question keeps its selection and draft. Ordinary updates and reload do not reopen a manually closed drawer; genuinely new questions can. Mobile foreground creation, Settings and skill search finish first; the question drawer opens afterward. Widening releases the drawer navigation layer while keeping the desktop panel open.

## Message images

Use **Add images**, paste image files or drag files into Composer. A message can contain text, images, or both. Remove any preview before sending. Limits: PNG/JPEG/WebP/non-animated GIF, up to **5 images**, **5 MiB each**, **20 MiB total**, **40 megapixels**, and **16383 pixels per side**. The execution Peer validates actual format and complete decoding; changing a filename or declared type does not bypass validation. Errors stay beside the draft or submission.

Full dimensions and decoded screenshot detail are retained. Sharp/libvips encodes true lossless WebP; it is adopted only when smaller and decoded RGBA matches exactly, including alpha. Otherwise the original bytes remain. Separate WebP thumbnails fit within 480px and 160KB; full images load on demand. File size does not establish model token cost or native consumption.

Image blobs persist in origin-scoped IndexedDB under the original Peer/Orc, with a 200 MiB/200-record device bound. Storage failures are explicit and prevent clearing the draft. Submission saves an immutable blob snapshot and delivery journal before clearing Composer and showing an immediate echo. Slow uploads, switching sessions, or newer drafts cannot move that submission. Preparation failures or explicit rejection restore complete text/images in the original conversation while retaining newer drafts. If recovery creates more than one batch's intake limit, remove images before sending again. Unknown outcomes query the original operation and never automatically resend; accepted receipts outrank late errors.

The browser uploads and reads directly from the original execution Peer, with existing origin/Peer identity and credential checks. Cross-origin requests use bearer authorization and explicit CORS preflight without cookies or public image links. Chord retains its 2 MiB frame limit and carries stable references only. Upload completion is separate from native admission. Native localImage inputs contain only Peer-validated stored paths; browser input cannot request arbitrary files. Proxy configuration must permit `/api/images` HTTP request bodies up to about 21 MiB, preserve Authorization/Origin/X-Grove-Peer, and allow GET/POST/OPTIONS.

Sharp is a runtime dependency installed by `bun install`; its supported platform binaries include libvips. The selected `--state` directory now contains private `media/` files and an atomic index, alongside workspace state. Unsubmitted uploads expire after 24 hours, checked on startup/upload, and are bounded to 100 operations/200 MiB. Referenced submissions and imported historical attachments are retained. Keep media with the workspace when backing up state. No deployment or restart is part of this change.

Sent Grove images and recoverable native thread image/localImage attachments display through authorized opaque references. Native membership is verified from that thread's actual item history; arbitrary paths and external image URLs are never fetched on browser request. Missing, unreadable, unsupported or oversized native attachments show an explicit placeholder; recovery of every historical attachment is not promised.

Execution feedback uses the fixed detail heading’s existing state/time position for Orcs and read-only Workers. Working shows the current turn’s elapsed time; Retrying appears only with explicit native `willRetry` evidence and keeps that time. Model at capacity and Execution error describe terminal failures with no active timer. Expand the status to read the full reason in a bounded scrolling area; the transcript does not repeat it. Current-turn native progress (non-empty agent delta, non-user item start or agent item completion), successful completion and a new native turn clear old feedback; steer admission alone does not. Thread/turn identity isolates late events. Codex owns request retries and stream recovery; Grove adds no retry, model switch or Worker creation. Peer outages and individual failed/unknown message recovery retain their own feedback.

There are no slash actions or proactive compact controls. A Working Orc has a circular stop-square button beside the independent circular Send button. Stop has no visible text; its tooltip and accessible name remain **Stop Orc**. Stop calls official SDK interruption for the **observed current Orc turn ID**; it never stops Workers. Stopping stays pending until an authoritative completion arrives. Confirmed user interruption returns Idle and shows feedback; a normally completed turn shows its actual outcome. Unknown acceptance stays unknown, never becomes success on a timer and never stops a later turn through replay. Reports, questions and uncertain deliveries remain available and retain close guards. A report received while Stopping is retained for explicit retry after the turn outcome.

**Option+X** on Mac or **Alt+X** elsewhere closes the current Orc tree: an open Orc detail takes precedence, otherwise the unique navigation Orc is the target. A Worker never implicitly closes its parent. The shortcut also works in ordinary Composer input, blocks character insertion, and pauses during temporary surfaces, title editing or IME. On mobile, swipe an Orc row left to reveal **Close this tree**, then tap to execute. Only one row exposes the action; swipe right or tap outside to collapse it. Vertical scrolling and ordinary row taps remain available, and Workers have no tree-close action. Close uses a dedicated Chord `closeTree` call directly to its execution owner, without sending a user message. Ask Orc to close its Workers first. Closure requires an idle Orc, no open Workers, no unanswered questions, no undelivered reports and no unconfirmed delivery. Success removes the tree and shows a three-second toast; refusal explains the guard beside the row or current detail. **Zero Workers is only a current count**; the application does not infer task completion or suggest closing from it.

The upper-right weekly ring shows **remaining account quota** from the page Peer. This deployment uses one Codex account across all execution hosts; multi-account catalogues are unsupported. The page Peer supplies quota and new-session preference catalogues; current-session choices come from the execution Peer. Execution hosts validate model, effort and Fast capabilities when creating or updating sessions. The quota reader chooses the official window with `windowDurationMins: 10080`, regardless of primary/secondary position. Remaining is clamped `100 - usedPercent`; missing data is a dash until a valid page-Peer cache exists. Quota buckets are never summed. Cyan is normal; amber means 20% or less. The popover shows account identity, page-Peer source and supplied reset time. All selected trees share one origin-scoped page-Peer quota cache, including on mobile. Requests poll every 60 seconds and manual refresh remains available; overlapping page-Peer requests are shared. Failed refreshes, missing numeric values and browser disconnection retain the last valid percentage and metadata through remounts and reloads. Reset time appears only when supplied.

## Browser and development

HTML preview links and tabs can navigate inside the sandbox. Close and parent navigation skip those internal history steps, keeping the outer controls responsive; native browser Back still traverses the iframe history. This preview navigation uses the Navigation API supported by Safari 26.2+ and current Chrome.

On desktop, drag an Orc row to reorder its whole tree within the selected device. Workers stay with their owner. The browser remembers a separate qualified root order per device across refresh; new roots append and successful authoritative removals prune the order. Offline data never clears it. Option+J/K, Cmd+1–9 and arrow navigation follow this visible order. Mobile uses the saved order without drag and retains swipe Close.

Close waits for native `thread/closed`, after Codex has shut down that thread and released its writer ownership, before removing the Orc or Worker from Grove. An unsubscribe acknowledgement alone is insufficient. Timeout/disconnection remains visible and retryable with an unconfirmed outcome; other threads in the shared Grove-owned app-server keep running. Grove starts its own process with zero idle unload delay and never changes user configuration or the system daemon.

**Option/Alt+H/L** uses physical H/L to select the previous/next configured device in button order, wrapping at either end. It works inside Composer and reuses device-button restoration of qualified sessions, drafts and reading state, including offline devices. Zero or one device does nothing. IME composition, Meta/Ctrl/Shift combinations and the same foreground navigation layers as Option+J/K block it; repeated keys are ignored while a device switch is in progress.

Shortcuts: up/down moves through visible sessions with first/last wrap and scrolls the selected row into view; **Option+J/K** moves next/previous using the same filtered order, including expanded Workers. **Cmd+1–9** selects the corresponding first nine visible sessions; a missing index does nothing and Cmd+0 is not bound. Both shortcuts work inside Composer, preserve each session’s draft and focus the target Orc’s message input. Workers remain read-only. Right expands an Orc or enters its first Worker; left collapses an Orc or locates a Worker’s parent. Desktop arrow navigation switches the persistent detail and highlights only that session; in the mobile list, Enter opens the navigation item. E toggles Workers, N opens creation with project-search focus, I focuses the Orc composer, Escape dismisses the top visible layer, and ? shows help. Ordinary arrows retain text-editing precedence; IME composition and foreground panels (creation, settings, skill search and other temporary surfaces) block session shortcuts. **Option+S** on Mac / **Alt+S** elsewhere opens skill search for the editable Orc, using the physical S key and preserving the draft and caret/selection even outside Composer focus. Mobile has a skill icon beside Add images. IME composition, other modifier combinations and foreground panels retain their own input. `$` is ordinary draft text and never opens search. Tab or Enter selects the current skill and inserts its exact `$skill-name` at the saved selection; Esc or Back restores the draft and selection. Tab keeps the input target; Enter sends, Shift+Enter inserts a newline. Send remains clickable and Stop has its own control while Orc is working. Tree closure produces a three-second toast.

On mobile, browser Back, the on-screen return and Esc unwind the same visible layers: a question drawer, dialog, skill search, quota popover, title edit or host filter closes before its underlying conversation. A Worker opened from an Orc returns to that Orc; a detail opened directly from the list returns to the list. List switching first dismisses active transient layers, then replaces the entire conversation journey with one detail that returns to the list, including switches from a nested Worker. Forward restores valid targets; refresh restores detail with a list return target. Closed targets resolve to a valid parent or list. The mobile root list allows normal browser departure. Desktop detail has no Close or collapse action; Escape dismisses a foreground layer or open question rail and otherwise retains the current conversation. Returning preserves drafts, scroll and expansion and does not send, Stop or Close an agent.

A small circular Lucide **Jump to bottom** icon button appears at the lower-right of the Orc/Worker conversation when reading above the bottom. Clicking scrolls to the end and restores automatic following. Reading above the bottom pauses following; short conversations and the bottom hide the button. It stays within the transcript, above Composer or the Worker footer.

## Generated file previews

Click a local PNG/JPEG/WebP/GIF, HTML/HTM or Markdown link in an Orc/Worker message, restored conversation or expanded Worker report to read it beside the conversation. Desktop previews cover about 80% of the detail pane at full height; mobile uses the full conversation area. The compact heading contains the filename, **Open in new tab** and **Close**. Close, parent-page Escape and browser Back return to the conversation, retaining message/image drafts and reading position. The heading remains available when an HTML report owns keyboard focus. Opening another file replaces the current preview. Questions share this space: their current answer and scroll remain intact, new questions wait, and closing the preview restores the prior question panel.

The original execution Peer resolves absolute paths, local `file:` URLs and paths relative to that agent’s working directory. A Worker report uses its original reporting Worker, including after that Worker closes. The entry must be a regular file inside the canonical session directory or an active og registered project directory on that same execution Peer. Relative links still resolve against the agent’s directory; absolute paths and `file:` URLs can select another registered project. New access reads the Peer’s current project catalogue; unavailable unrelated roots are skipped, and catalogue failure permits only the session directory. Another Peer’s catalogue never authorizes local files. Its containing directory becomes the preview’s resource root; supported resources in that directory and subdirectories include images, CSS, JavaScript/modules, JSON and WOFF/WOFF2/TTF/OTF fonts. Parent-directory references, symlinks escaping the allowed canonical roots, directory listings and unsupported files are refused. Resource reads remain confined to the granted directory even when another project is registered. Each read is limited to 20 MiB. Missing/unreadable files, an offline Peer or expired access offer explicit Retry without sending an agent message.

HTML retains its own presentation and can run scripts and load external HTTP(S) CDN resources. Both the embedded frame and directly opened HTML/Markdown use a browser sandbox with scripts allowed and same-origin, forms, popups and top navigation permissions withheld. Markdown escapes raw HTML and keeps code/table scrolling local to the content. This supports standalone reports, not a development server or general web application. No download control or arbitrary HTTP/localhost proxy is provided.

Preview access uses a random, short-lived capability scoped to the original Peer and canonical resource directory, held only in memory: 15 minutes, at most 256 grants per Peer HTTP handler. Restart or expiry requires reopening/Retry; closing the drawer leaves an already-open tab usable until expiry. URLs expose neither the original machine path nor the Peer’s long-lived access credential. Responses use no-store/no-referrer/nosniff; the service worker excludes previews. Only valid capability resources permit opaque-origin CORS. Creating access retains existing origin/authentication/Peer identity checks; ordinary API and WebSocket authorization is unchanged. Forward/refresh retain only the agent and original link and create fresh access.
