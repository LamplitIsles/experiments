# FlickGrove

A persistent Orc/Worker workspace with symmetric Peers. Every Peer serves the same frontend and owns its local session trees. Open any reachable Peer, then configure additional hosts in that browser. The browser connects directly to each Peer; the page host does not relay remote business calls. Closing a browser leaves execution running.

```sh
bun install
bun run --cwd flickgrove build
bun run --cwd flickgrove start --name "Neil’s Mac"
# The same command runs a Peer on NUC; there is no --hub role.
bun run --cwd flickgrove start --name NUC
```

The default address is **http://127.0.0.1:4318**. Each execution machine needs an authenticated `codex` executable and its own `og` project registry. Agents run with the repository's full-access local Codex policy. Codex configuration is inherited, never rewritten.

## Connections and browser preferences

Use `--listen`, `--port` and `--origin` for an existing HTTP(S) proxy/tunnel. This application does not provision tunnels. The configured origin has no path, query or embedded credentials. Proxies preserve Host and WebSocket upgrades on `/api/socket`, including `Sec-WebSocket-Protocol`. Local agent MCP calls use `http://127.0.0.1:PORT` and separate per-agent tokens, independently of the advertised browser origin.

`--state DIRECTORY` selects durable state (default `~/.local/share/flickgrove`); `--codex PATH` selects the executable. `workspace.sqlite` owns conversations and each tree's captured execution settings. Private mode-0600 `hosts.json` stores only the stable Peer identity and access credential. Read the remote credential locally and enter it under **Settings → Hosts → Add host**. The browser stores host addresses and credentials in origin-scoped local storage; another browser, device or page origin has independent configuration. There is no configuration synchronization or backend host directory.

Registration opens a direct WebSocket, authenticates and checks stable identity before saving. Self/duplicate identities and identity swaps on address edits are rejected. An edit may leave the masked token field blank to keep its browser-stored token. Addresses must be reachable from the accessing device: `localhost` refers to that device, not the machine providing the page. A secure page also requires browser-compatible secure remote endpoints.

Same-origin browser sockets use the page Origin. Cross-origin sockets authenticate using the `grove.v1` and `grove-auth.CREDENTIAL` subprotocols; credentials do not appear in request URLs. No workspace state or execution operation is exposed over unauthenticated HTTP. Chord carries calls and replicated local list/selected-detail state. Peer-qualified session IDs prevent collisions; agent MCP tokens never appear in public state.

Settings save this browser's **new-session preferences**: Orc/Worker model and effort, Fast, and selected execution host. Creating a session explicitly sends settings to that Peer, which validates capability without silently downgrading. The tree captures both Orc and Worker execution settings; future Workers use their Orc's captured configuration, including after restart. Later browser preference changes cannot modify existing trees. There is no global settings push between Peers.

## Independent connections and recovery

Each browser-to-Peer connection independently reconnects and retains its last-known read-only cache. Remote failure disables only that Peer's writes; reachable Peers remain usable. Standard WebSocket Ping/Pong on each server checks the browser connection. The browser also uses a lightweight identity probe to detect a stalled path because browser WebSocket has no Ping API. Business request deadlines reject individual requests without closing the socket. No quota or model query acts as a heartbeat.

Reconnection verifies identity and obtains a fresh authoritative snapshot. Each browser/connection independently selects its visible detail. Closing an observation connection does not interrupt execution.

Each message has an operation ID. An unknown result is reconciled against the owning Peer and is never automatically replayed. Accepted receipts clear uncertainty; pending, missing and uncertain results remain distinct. After checking the conversation, **I checked — remove local pending item** dismisses only browser-owned pending state. It does not resend, declare success, remove server history or bypass server close guards.

## Native runtime ownership

Each execution host lazily starts **one Grove-owned managed Codex app-server** for all of its Orc/Worker handles, history/model/skill/usage catalog reads and title threads. Concurrent opens share the same connecting client. Grove uses the existing explicit executable path, environment and bootstrap; it does not attach to, start or manage a system daemon.

Thread start/resume carries each agent’s cwd, role instructions, model/effort/service tier and private MCP token. Native notifications are filtered by thread ID. Native synchronous requests without an owned thread are rejected; Grove’s async question/MCP flow remains the supported interaction and no approval/tool consumption is fabricated. Stop targets only its observed thread/turn. Closing an agent aborts its title task and unsubscribes only its native thread, leaving Codex’s native unload lifecycle and other threads intact. Tree/report/question closure guards and native writer locks remain in force.

A shared process disconnect affects its open agents together. They show interrupted/unknown results; the next explicit operation reconnects the managed client and resumes the original thread. Unknown submitted inputs are not replayed. Closing a browser releases only observation. Shutting down Grove closes its managed client. Isolated tests observe one process for two concurrent agents plus catalog/title work, versus the previous per-agent processes and separate catalog process. This is process-count evidence; no measured memory or CPU saving is claimed.

## Conversation controls and usage

Press **N**, choose an execution host and one of its registered projects, then select **Find history** to search that directory's Codex sessions by title or first message. The list includes CLI sessions and archived or Grove-closed sessions. Search uses Codex's SQLite-backed metadata through app-server `thread/list`; Grove does not open the database directly or build a second search index. Indexed metadata is paginated across projects and filtered on the execution host by filesystem directory identity, so casing and symlink aliases can match without merging distinct directories on case-sensitive filesystems. Preview reads paginated conversation items without copying them into Grove's database. Restoring a closed Orc refreshes its history boundary, so CLI continuation during closure is visible too. Captured Grove turns replace their native history counterparts by turn identity to preserve Worker report cards; pagination deduplicates those captured groups. Only the boundary and captured-message count are added to workspace metadata, not another history-message copy.

Resume continues the original thread without sending a message. CLI sessions become Orcs with their existing model, reasoning effort and service tier; closed Grove Orcs retain their identity and keep old Workers closed. Workers remain read-only and link to their owning Orc. Already open sessions open their existing detail. Codex's writer lock rejects sessions held by another instance; the preview shows the error and permits explicit retry after that instance releases it. Grove never removes locks or forces ownership. The execution host must run a Codex app-server supporting indexed `thread/list`, paginated items and writer locks.

Open-session rows and history results use two compact lines. Execution state and input needs sit at the upper-right, while Worker disclosure and counts share the metadata line. They do not consume separate rows. The open-session metadata line includes a muted Lucide GitBranch indicator, with branch text capped at 12ch, ellipsis and the complete value in its title. It shows the current checkout of the session’s registered working directory, including a worktree’s own branch; it does not track tool-local `cd` or freeze the branch at creation. Workers sharing their Orc’s directory omit the duplicate indicator; a different directory shows its own value even when branch names match.

Each execution Peer deduplicates open-session directories (including symlink aliases), reads local Git metadata promptly on startup/new directories and polls about every five seconds after a completed cycle. At most two reads run concurrently, each Git subprocess has a 1.5-second limit, and no network Git operation runs. Only changed values publish through the existing Chord snapshot/detail and Peer-specific browser cache. Non-repositories show nothing and explicitly clear an earlier value; detached HEAD shows `@` plus a short commit, and unborn branches show their name. Query failures and offline Peers retain the last successful value, with no unknown placeholder or freshness label. Closing the last session stops its directory’s reads; shutdown aborts queries and discards late results. Branch state stays in Peer memory, without a database copy, and is reread on Peer startup.

Send ordinary instructions to Orc. An idle Orc uses native `turnStart`; new input during execution uses `turnSteer` immediately in submission order, without waiting for the model’s answer. Each submission has its own stable operation ID, separate from a socket request ID and native turn ID. The browser persists each operation in its own origin/agent-scoped record before invocation, so another tab cannot erase pending content or identity. It echoes it immediately and clears the submitted draft so editing and further sends remain available. Sending stays disabled while offline or Stopping, while an offline draft remains editable.

An accepted receipt proves native input acceptance, not model consumption or completed work. Success displays the ordinary message without an Accepted/success label or internal sending/queued status line. Failed messages retain a user-facing attention prompt, the specific reason and recovery action; unknown messages remain explicitly unconfirmed with receipt lookup. This applies to text, image and question-answer timeline messages; Worker report cards and the question panel’s busy feedback are unchanged. Success adds no toast. A rejected user message can be restored alongside a newer draft for an explicit new submission. Unknown messages retain their text and **Check receipt** action; lookup reads saved owner-side evidence and never calls a model. Native acceptance followed by a crash before saving its result remains unknown. A late error cannot erase an already observed submission. Failed Worker reports retain an explicit Retry action with their original report identity; unknown reports keep their existing closure guard.

`$` opens the candidate panel directly above Composer, with an independent search field over the owning host's project. Search matches skill names and full descriptions with Organon-style ranking, plus fuzzysort name-only abbreviation matching (for example, `grdo` finds `grill-with-docs`); Tab or Enter inserts the selected name at the saved cursor position without sending. Up/down selects a candidate; Escape or browser Back cancels and restores the draft and caret. Models and effort are settings, not skill arguments. Session titles are generated from the first message in a separate lightweight-model thread. This application does not create, merge or deploy PRs itself.

Click an Orc title in its detail panel to edit it. Enter or the checkmark saves; Escape or Cancel discards the edit. The owning execution host saves the canonical Codex thread name through `thread/name/set`, then updates its workspace display cache, including remote hosts. Failed saves retain the old title. Backend startup reads Orc names without resuming turns; explicit thread resume refreshes them again. Unreachable Codex reads retain the last cached title. Changing a title sends no model message. Worker titles remain managed by Orc.

Workers are read-only in the browser. Orc can start, list, read, instruct and close only its own Workers through the host-local `flickgrove` MCP server. Workers report only to their parent. Orc and Worker sessions enable native multi-agent tools for independent review. Reviewer selection belongs to the applicable skills and agent configuration; Grove does not maintain a reviewer allowlist. Role instructions restrict native spawning to review; implementation delegation stays with FlickGrove Workers. The spawning session manages its native reviewers, which are not displayed as Workers in the Grove tree. This restriction is instruction-based, not enforced by the tool runtime. Worker async questions route to Orc; contextual replies resolve only explicit question IDs.

`worker_close` records a durable closure request. A ready Worker closes after native thread release succeeds; a running Worker completes its current turn without interruption and closes automatically once its reports are delivered and delegated questions are answered. Pending Workers show Closing and a waiting reason and reject new tasks; explicit answers to existing questions remain allowed. Failed terminal turns also permit closure. Restart or disconnection retains the request with an unknown outcome; Orc can inspect it and explicitly use `confirmInterrupted` to acknowledge the interruption, while report and question guards still apply. The user’s direct Close action retains the existing tree guards. Orcs and Workers stay visible with their handles until native unsubscribe succeeds. A failed release keeps them retryable: retry direct Close for Orc, or `worker_close` for Worker; automatic Worker release failure shows its reason and waits for an explicit retry. History restore waits for in-flight Close and reuses an agent whose failed release kept it open.

Incoming Worker reports appear on the left of the conversation timeline as folded cards. Expand a card to read its full Markdown; ordinary user messages remain separate. This uses existing delivery source and reporting Worker IDs and adds no report storage.

**All questions** opens a wide right drawer (about 600px on desktop, overlay on narrow desktop, full screen on mobile). One pending question is shown at a time, with persistent question position and Previous/Next controls. Left/Right switches questions anywhere in the non-editing question region; text caret arrows and radio Up/Down retain their normal meaning. Selection and answer drafts survive switching and reload. Option+J/K and Cmd+1–9 keep their existing question-panel behavior.

**Send all answers** or Enter freezes every currently pending question and answer into one immutable operation and one native start/steer. A missing answer selects the first unfilled question instead of sending. Shift+Enter inserts a newline; IME Enter only confirms composition. Repeated Enter during submission does not duplicate the batch. Questions arriving during submission belong to the next batch. Rejected batches retain the complete envelope for explicit **Retry**, revalidating all original questions. Unknown outcomes use **Check receipt** without replay. The same question-and-answer batch appears immediately as one user message with its actual delivery status; confirmation, reload and pagination converge on that original identity. Answered questions remain directly readable in the drawer, without a second history fold.

Background questions never switch the conversation. Returning to a session with unseen new question IDs opens its drawer without moving Composer focus. A current edited question keeps its selection and draft. Ordinary updates and reload do not reopen a manually closed drawer; genuinely new questions can. Mobile foreground creation, Settings and skill search finish first; the question drawer opens afterward. Widening releases the drawer navigation layer while keeping the desktop panel open.

## Message images

Use **Add images**, paste image files or drag files into Composer. A message can contain text, images, or both. Remove any preview before sending. Limits: PNG/JPEG/WebP/non-animated GIF, up to **5 images**, **5 MiB each**, **20 MiB total**, **40 megapixels**, and **16383 pixels per side**. The execution Peer validates actual format and complete decoding; changing a filename or declared type does not bypass validation. Errors stay beside the draft or submission.

Full dimensions and decoded screenshot detail are retained. Sharp/libvips encodes true lossless WebP; it is adopted only when smaller and decoded RGBA matches exactly, including alpha. Otherwise the original bytes remain. Separate WebP thumbnails fit within 480px and 160KB; full images load on demand. File size does not establish model token cost or native consumption.

Image blobs persist in origin-scoped IndexedDB under the original Peer/Orc, with a 200 MiB/200-record device bound. Storage failures are explicit and prevent clearing the draft. Submission saves an immutable blob snapshot and delivery journal before clearing Composer and showing an immediate echo. Slow uploads, switching sessions, or newer drafts cannot move that submission. Preparation failures or explicit rejection restore complete text/images in the original conversation while retaining newer drafts. If recovery creates more than one batch's intake limit, remove images before sending again. Unknown outcomes query the original operation and never automatically resend; accepted receipts outrank late errors.

The browser uploads and reads directly from the original execution Peer, with existing origin/Peer identity and credential checks. Cross-origin requests use bearer authorization and explicit CORS preflight without cookies or public image links. Chord retains its 2 MiB frame limit and carries stable references only. Upload completion is separate from native admission. Native localImage inputs contain only Peer-validated stored paths; browser input cannot request arbitrary files. Proxy configuration must permit `/api/images` HTTP request bodies up to about 21 MiB, preserve Authorization/Origin/X-Grove-Peer, and allow GET/POST/OPTIONS.

Sharp is a runtime dependency installed by `bun install`; its supported platform binaries include libvips. The selected `--state` directory now contains private `media/` files and an atomic index, alongside workspace state. Unsubmitted uploads expire after 24 hours, checked on startup/upload, and are bounded to 100 operations/200 MiB. Referenced submissions and imported historical attachments are retained. Keep media with the workspace when backing up state. No deployment or restart is part of this change.

Sent Grove images and recoverable native thread image/localImage attachments display through authorized opaque references. Native membership is verified from that thread's actual item history; arbitrary paths and external image URLs are never fetched on browser request. Missing, unreadable, unsupported or oversized native attachments show an explicit placeholder; recovery of every historical attachment is not promised.

Execution feedback uses the fixed detail heading’s existing state/time position for Orcs and read-only Workers. Working shows the current turn’s elapsed time; Retrying appears only with explicit native `willRetry` evidence and keeps that time. Model at capacity and Execution error describe terminal failures with no active timer. Expand the status to read the full reason in a bounded scrolling area; the transcript does not repeat it. Current-turn native progress (non-empty agent delta, non-user item start or agent item completion), successful completion and a new native turn clear old feedback; steer admission alone does not. Thread/turn identity isolates late events. Codex owns request retries and stream recovery; Grove adds no retry, model switch or Worker creation. Peer outages and individual failed/unknown message recovery retain their own feedback.

There are no slash actions or proactive compact controls. A Working Orc has a circular stop-square button beside the independent circular Send button. Stop has no visible text; its tooltip and accessible name remain **Stop Orc**. Stop calls official SDK interruption for the **observed current Orc turn ID**; it never stops Workers. Stopping stays pending until an authoritative completion arrives. Confirmed user interruption returns Idle and shows feedback; a normally completed turn shows its actual outcome. Unknown acceptance stays unknown, never becomes success on a timer and never stops a later turn through replay. Reports, questions and uncertain deliveries remain available and retain close guards. A report received while Stopping is retained for explicit retry after the turn outcome.

**Option+X** on Mac or **Alt+X** elsewhere closes the current Orc tree: an open Orc detail takes precedence, otherwise the unique navigation Orc is the target. A Worker never implicitly closes its parent. The shortcut also works in ordinary Composer input, blocks character insertion, and pauses during temporary surfaces, title editing or IME. On mobile, swipe an Orc row left to reveal **Close this tree**, then tap to execute. Only one row exposes the action; swipe right or tap outside to collapse it. Vertical scrolling and ordinary row taps remain available, and Workers have no tree-close action. Close uses a dedicated Chord `closeTree` call directly to its execution owner, without sending a user message. Ask Orc to close its Workers first. Closure requires an idle Orc, no open Workers, no unanswered questions, no undelivered reports and no unconfirmed delivery. Success removes the tree and shows a three-second toast; refusal explains the guard beside the row or current detail. **Zero Workers is only a current count**; the application does not infer task completion or suggest closing from it.

The upper-right weekly ring shows **remaining account quota** from the page Peer. This deployment uses one Codex account across all execution hosts; multi-account catalogues are unsupported. Only the page Peer supplies UI quota and model catalogue; execution hosts still validate model, effort and Fast capabilities when creating sessions . The quota reader chooses the official window with `windowDurationMins: 10080`, regardless of primary/secondary position. Remaining is clamped `100 - usedPercent`; missing data is a dash until a valid page-Peer cache exists. Quota buckets are never summed. Cyan is normal; amber means 20% or less. The popover shows account identity, page-Peer source and supplied reset time. All selected trees share one origin-scoped page-Peer quota cache, including on mobile. Requests poll every 60 seconds and manual refresh remains available; overlapping page-Peer requests are shared. Failed refreshes, missing numeric values and browser disconnection retain the last valid percentage and metadata through remounts and reloads. Reset time appears only when supplied.

## Browser and development

Shortcuts: up/down moves through visible sessions with first/last wrap and scrolls the selected row into view; **Option+J/K** moves next/previous using the same filtered order, including expanded Workers. **Cmd+1–9** selects the corresponding first nine visible sessions; a missing index does nothing and Cmd+0 is not bound. Both shortcuts work inside Composer, preserve each session’s draft and focus the target Orc’s message input. Workers remain read-only. Right expands an Orc or enters its first Worker; left collapses an Orc or locates a Worker’s parent. Desktop arrow navigation switches the persistent detail and highlights only that session; in the mobile list, Enter opens the navigation item. E toggles Workers, N opens creation with project-search focus, I focuses the Orc composer, Escape dismisses the top visible layer, and ? shows help. Ordinary arrows retain text-editing precedence; IME composition and foreground panels (creation, settings, skill search and other temporary surfaces) block session shortcuts. **Option+S** on Mac / **Alt+S** elsewhere opens skill search for the editable Orc, using the physical S key and preserving the draft and caret/selection even outside Composer focus. Mobile has a skill icon beside Add images. IME composition, other modifier combinations and foreground panels retain their own input. `$` is ordinary draft text and never opens search. Tab or Enter selects the current skill and inserts its exact `$skill-name` at the saved selection; Esc or Back restores the draft and selection. Tab keeps the input target; Enter sends, Shift+Enter inserts a newline. Send remains clickable and Stop has its own control while Orc is working. Tree closure produces a three-second toast.

On mobile, browser Back, the on-screen return and Esc unwind the same visible layers: a question drawer, dialog, skill search, quota popover, title edit or host filter closes before its underlying conversation. A Worker opened from an Orc returns to that Orc; a detail opened directly from the list returns to the list. List switching first dismisses active transient layers, then replaces the entire conversation journey with one detail that returns to the list, including switches from a nested Worker. Forward restores valid targets; refresh restores detail with a list return target. Closed targets resolve to a valid parent or list. The mobile root list allows normal browser departure. Desktop detail has no Close or collapse action; Escape dismisses a foreground layer or open question rail and otherwise retains the current conversation. Returning preserves drafts, scroll and expansion and does not send, Stop or Close an agent.

A small circular Lucide **Jump to bottom** icon button appears at the lower-right of the Orc/Worker conversation when reading above the bottom. Clicking scrolls to the end and restores automatic following. Reading above the bottom pauses following; short conversations and the bottom hide the button. It stays within the transcript, above Composer or the Worker footer.

Chrome notification permission is requested at first pointer interaction. Notifications cover idle transitions, errors and new questions while the page is open, suppress replay after reconnect, and open the corresponding Orc. Install the PWA through Chrome or the progressive install action. Its service worker caches the built shell/fonts, never API responses. Offline reload restores cached conversations and drafts with sending disabled. Peer access credentials live in browser storage; agent credentials remain server-side.

For development, start a Peer backend, then run `bun run --cwd flickgrove dev`. The Vite API proxy targets port 4318; development does not install a service worker.

## UI foundation

Desktop session creation uses N; ? opens shortcut help. Hosts management lives in Settings. A fixed narrow session list stays usable beside the detail, whose metadata sits above the editable title. Orc roots retain snapshot order and show host/project, work state, input needs and current total/working Worker counts. Worker navigation appears only in this tree, including on mobile; return to the list to open a Worker. Workers default to collapsed and use indented, small titles clamped to two lines. With detail open, its session is the only highlighted row. On the mobile list, a single keyboard navigation marker locates the item to open. Execution state remains separate. Mobile retains a New session button.

The frontend uses project-owned shadcn-svelte components (Bits UI), Lucide icons and a compact dark workbench theme. Read [DESIGN.md](DESIGN.md) before changing the component layer. Ordinary buttons do not retain visible focus rings after pointer actions. No compact-tree Penpot board exists; screenshots assess rendered usability. Browser checks use 1440px and 390px Chrome; real Android/PWA soft keyboards and iOS back gestures need device acceptance.
