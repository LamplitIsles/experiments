# FlickGrove

A persistent Orc/Worker/Reviewer/Researcher workspace. One instance owns its session trees and native agent processes. Codex projects execute on that instance's machine or a configured SSH Mac; the Mac runs an executor and project tools. Closing the browser leaves execution running.

```sh
bun install
bun run --cwd flickgrove build
bun run --cwd flickgrove start --name "Neil’s Mac"
# The same command runs a Peer on NUC; there is no --hub role.
bun run --cwd flickgrove start --name NUC
```

The default address is **http://127.0.0.1:4318**. Codex authentication and App Server stay on the instance machine. Each project device needs its own `og` project registry and existing forge authentication. Pi runs through the pinned local SDK installed by `bun install`, without upgrading a global Pi installation, and supports projects on the instance machine only. Codex Orc and Worker threads use the full-access policy in their selected environment; Codex Reviewer and Researcher threads use the native read-only sandbox on creation and restoration, including settings readback and close retry. Fixed role instructions keep all implementation and repairs with Workers and prohibit Reviewer verification. Responsibility instructions and native filesystem sandbox are separate from Grove's role-authorized MCP tools and server guards. Grove never rewrites the user's Codex configuration.

## Project execution environments

Spec **#4424** keeps Grove, Codex App Server and agent sessions, FlickNote and FlickLog on the instance machine. An SSH Mac supplies checkout files, the compatible native `codex exec-server`, `og`, Git and `python3` (3.9 or newer) for bounded project/preview reads. It does not need a separate Grove or agent session. No deployment, device application installation, credentials synchronization or real n5pro→Mac connection is performed by this change.

Administrators add the matching stable ID to the instance configuration (`~/.config/flickgrove/config.toml`, or `--config PATH`):

```toml
[[project_environments]]
id = "mac"
name = "Mac"
ssh = "mac"
og = "/absolute/path/to/og"
```

In the **instance machine's** `$CODEX_HOME/environments.toml` (normally `~/.codex/environments.toml`), use this non-interactive SSH argument order. Replace only the SSH alias and executor path:

```toml
include_local = true
default = "local"

[[environments]]
id = "mac"
program = "ssh"
args = ["-T", "-o", "BatchMode=yes", "-o", "StrictHostKeyChecking=yes", "-o", "ConnectTimeout=5", "mac", "/absolute/path/to/codex exec-server --listen stdio"]
initialize_timeout_sec = 10
```

Both IDs and aliases must match. SSH aliases come from trusted administrator configuration. Existing host-key verification is mandatory: register the verified device key in a configured known-hosts file beforehand. Grove never accepts a new key, prompts for passwords or installs tools. It captures the effective SSH destination, native transport and public known-host keys as a non-secret digest in the existing Project snapshot. Changing the destination/key/transport refuses old-session execution and outstanding preview grants; restore the original configuration to continue the original tree. App Server captures its environment definitions at startup, so restart Grove after changing them before creating a session for the new configuration. Removing an environment retains saved conversations and attachments. No schema migration or cross-device session move occurs.

New session offers **Execution environment** before the existing searchable Project choice when more than one environment is configured. With only the instance machine, the additional choice is omitted. Project discovery runs that environment's `og project list --json`. Same aliases and path strings on different devices remain distinct. Every tree fixes its environment; Workers, Reviewers and Researchers may choose another registered project in that same environment. Pi Orc/Worker defaults or Pi Reviewer/Researcher profiles are rejected before remote admission, without changing the backend. Change the corresponding application setting to Codex.

Each new Codex thread and execution turn explicitly selects its saved environment. Original-thread recovery rechecks its captured target and uses the same binding for subsequent turns; steering keeps the already accepted native turn. Native environment lists after resume can include `local` as well as the saved executor; that list alone does not establish Grove ownership. Managed history uses the saved Project binding, and cursors cannot cross environments. A remote native history without Grove's original target snapshot cannot be assigned to a device or adopted for execution. In the existing environment/project picker, **Saved history** entries come from persisted Project snapshots, including closed trees and removed environments. When alias, environment, captured target and path match a current registration, the picker shows only that registration, with both New session and Find history available. An unbound local snapshot has the same local identity as an explicit local binding. Unmatched snapshots retain their separate Saved history entry and cannot create a new session. Their history lists, previews and full message bodies read the centralized native transcript without live SSH project discovery or writer admission. Saved entries keep separate target identities when an environment ID is retargeted; history cursors cannot cross those targets. New-session creation uses live registered projects; explicit resume and remote file previews still require the original execution target to be available. Device unavailability reports an error for the requested operation; it never switches devices, changes engines or resends unknown submissions. Browser→Grove connectivity remains separate from project-device connectivity.

`og mcp` runs through the selected native executor, with the same checkout and remote `og` executable used for discovery. Remote og is a required native MCP: startup failure refuses opening the thread. The Grove collaboration MCP explicitly runs in `local`, and its private token stays on the instance machine. Other MCP services keep their configured ownership; there is no “move all MCP” switch. User uploads and native message images retain instance storage ownership. Native image inputs are prepared by the centralized App Server rather than treating upload paths as Mac paths.

For a remote conversation, Composer searches **Grove instance skills**: enabled user/admin/system/plugin skills and shipped Grove workflows discovered by native `skills/list` from the instance Codex configuration root, excluding repository-scoped results. It never queries that API with a remote checkout path. Native execution still loads the remote project's AGENTS/skills, and explicit selection of a centralized skill loads its body through native host skill roots. This does not scan, copy or install remote project candidates. Local project skill discovery keeps its existing behavior.

HTML, Markdown, images and their relative resources use the existing conversation-authorized preview contract. A remote grant captures the environment/target digest and the device's canonical resource root. Every relative read rechecks the captured target, root and symlink containment, regular-file requirement and 20 MiB limit. Existing 15-minute TTL, read-only HTTP, CORS and HTML sandbox policies apply. Disconnects and changed targets fail closed, even when a same-named local file exists. There is no unauthenticated SSH file endpoint or general remote file browser.

Browser, WeChat developer tools and Blender remain fixed to the Mac independently of the project environment. Configure each device MCP separately on the instance machine, for example an administrator-owned SSH stdio command with `environment_id = "local"` that launches that tool's actual Mac executable. Retain its normal authentication and application permissions. FlickNote's loopback service, FlickLog's collection/query entry point and the Grove bridge remain centralized. This PR does not configure those applications or verify real FlickLog hooks or production deployment.

## Composer and voice input

Spec **#3685**, discussion **#3683**: below the draft, the first row has Add images, voice and Skill search on desktop and mobile; Stop Orc and Send stay at the right. The second row contains Discuss, Implement, Review, Re-review, Research and Diagnose (order spec **#3727**). On mobile only that second row scrolls horizontally. Skills prepare the invocation at the saved caret; sending still requires an explicit action.

Each Peer that needs voice must independently configure its server-side key file in the existing runtime configuration (`~/.config/flickgrove/config.toml`, or `--config PATH`):

```toml
[voice]
api_key_file = "voice-api-key"
```

Relative paths resolve against the config file's directory; absolute paths also work. `voice-api-key` contains a single UTF-8 API key, optionally followed by a newline. Keep it private (`chmod 600 voice-api-key`); files readable/writable/executable by group or others, empty/invalid keys, files larger than 1 KiB and missing/unreadable paths disable voice. The application never creates this key file. Do not put the key into the TOML, repository, browser host credentials or agent MCP configuration. Config/key are read afresh on capability checks and every new voice connection; an active take retains its captured key. No restart is needed for voice-only changes: reopening the conversation, reconnecting or reloading refreshes availability, and starting a take checks again. Existing mandatory Orc/Reviewer/Researcher startup validation remains unchanged.

Use HTTPS or localhost and a browser supporting microphone access, AudioContext at actual 16 kHz and AudioWorklet. Availability checks run silently; unsupported capture or missing/unavailable configuration disables only the microphone, with its reason in the title/accessibility description, and leaves text and images usable. Starting microphone, Recording elapsed time and Recognizing appear inline in the first-row Skill search slot; Skill search returns after success, cancellation or failure without adding a status row. Click the microphone to start; click Stop recording at the same position to recognize. From microphone permission/startup through recognition, the draft is read-only, Send/Skill/image changes are disabled, and Add images becomes Cancel. Stop Orc remains a separate execution action. Only the final text replaces the original selection or inserts at the captured caret; it never sends automatically or shows intermediate results. Failures/empty results preserve the draft. Cancel/Escape, hidden page, navigation, conversation/Peer changes, recovery and disconnection invalidate the take and release capture/transport resources; Escape preserves the existing foreground surface hierarchy.

Local voice capture and the fresh local instance capability/recognition connection prepare concurrently after an explicit microphone click. Recording and elapsed time begin on the first actual PCM frame, independently of server readiness. Up to five seconds (160,000 bytes) of startup PCM stays in memory; overflow fails the take instead of dropping speech. Only verified local instance ready permits ordered audio delivery. A short Stop flushes and releases capture immediately, then waits for readiness to deliver all retained frames before Finish. The 15-second startup bound remains effective while server readiness is pending, including during local Recording and after a short Stop; cancellation discards queued audio and invalidates late setup/results. No microphone or provider task is prepared before the click. Physical-device startup latency remains unmeasured.

The browser uses the current instance’s same-origin `GET /api/voice/capability` and WebSocket `/api/voice/stream`. Origin/address and stable instance identity checks guard access; no browser Peer credential is needed or accepted as cross-origin authorization. Agent MCP tokens remain separate. The key and raw provider frames never reach public state or the browser.

The relay fixes DashScope `wss://dashscope.aliyuncs.com/api-ws/v1/inference` and `qwen-audio-3.1-asr-flash-streaming`, following [the official client protocol](https://help.aliyun.com/zh/model-studio/qwen-audio-asr-streaming-client-events). Capture streams mono PCM16 little-endian at 16 kHz in approximately 100 ms frames without buffering a whole recording or adding a resampling fallback. Limits: five minutes/9,600,000 PCM bytes, nonempty even frames up to 16 KiB, 256 KiB send queue, 128 KiB upstream events and 20,000 Unicode codepoints of final text; startup 15 s, finish 20 s, absolute relay lifetime 320 s from ready. Valid empty sentence finals close their interim segment without stopping recording; only usable text contributes to the final draft. Sentence finals are deduplicated and sorted by ID; invalid/unfinished/abnormal termination produces no draft change.

The relay does not persist or log audio or transcripts. The resulting draft uses the existing browser-local draft storage, and only an explicit Send creates a normal message. Cancel closes connections but cannot retract audio already streamed to DashScope or guarantee cancellation of provider processing/billing. No audio messages, service deployment or provider settings UI are added.

Isolation verification: `bun test server/voice.test.ts` and `bun run test:browser tests/composer-voice.spec.ts` exercise synthetic private keys, fake upstreams and an actual AudioWorklet with synthetic microphone audio. Desktop 1440/mobile 390 screenshots are saved under `.scratch/composer-voice-two-rows/screenshots/`. Physical-phone microphone capture and real provider latency/billing are not verified by these tests.

## Connections and browser preferences

Use `--listen`, `--port` and `--origin` for an existing HTTP(S) proxy/tunnel. This application does not provision tunnels. The configured origin has no path, query or embedded credentials. Proxies preserve Host, Origin, X-Grove-Peer and WebSocket upgrades/subprotocols on `/api/socket` and `/api/voice/stream`. Local agent MCP calls use `http://127.0.0.1:PORT` and separate per-agent tokens, independently of the advertised browser origin.

`--state DIRECTORY` selects durable state (default `~/.local/share/flickgrove`); `--codex PATH` selects the executable. `workspace.sqlite` owns conversations and captured tree execution settings. `hosts.json` retains the stable local instance ID used to namespace browser caches and pending submissions. New files contain only the ID. Existing files are read without rewriting; obsolete credential fields have no authority. No saved sessions or pending operations are migrated or deleted.

Same-origin browser sockets use the page Origin and `grove.v1`; no Peer token is needed. Legacy bearer headers or auth subprotocols do not affect same-origin access. Foreign and missing browser origins are rejected, even with a former Peer token. Reading/media requests allow same-origin Fetch Metadata when Origin is omitted. Chord carries local calls and replicated list/selected-detail state. Instance-qualified IDs preserve durable ownership and pending receipt identity; they never select a remote route. Agent MCP tokens never appear in public state.

Settings save this browser’s **new-session preferences**: Orc/Worker model and effort and Fast. Creation selects a local registered project and explicitly sends settings to this instance, which validates capabilities without silently downgrading. Each tree captures both Orc and Worker execution settings, including across restart. Later browser preference changes do not modify existing trees.

Press **N** to search registered projects immediately by alias or name. Arrow keys browse and Enter chooses a project; **New session** creates it. Find history preserves that project search when returning. Model choices are searchable and show their provider and ID; backend and effort use the same project-styled choice controls. Escape or browser Back dismisses an expanded choice before its containing dialog. Unavailable saved choices stay visible until explicitly replaced.

The opened Orc or Worker has an individual **Session settings** control for Model and Reasoning effort with atomic Save/Cancel (**Option/Alt+M**). A separate **Tree Fast** Zap control (**Option/Alt+F**) targets the owning Orc and all open editable Workers, Reviewers and Researchers, and sets the Fast policy for future Workers. The Orc list indicator shows this desired tree policy. Unsupported models stay on their original model at standard speed; the control tooltip explains capability and the confirmed next-turn tier. Model/effort changes affect only the selected agent and recompute its tier from the tree policy. Physical-key shortcuts preserve Composer drafts/selection; IME, title editing and foreground panels block them.

Changes use native `thread/settings/update` on original shared app-server threads. Each member's confirmed settings remain authoritative; multi-thread updates are not atomic. Explicit tree mutations persist desired policy within the owning tree; other trees, model/effort defaults and browser new-session preferences remain independent. Changes affect subsequent new turns; current work and `turn/steer` retain their configuration. Partial failure or unknown outcomes remain actionable beside the control. Explicit Retry first reads native settings before any necessary update; no automatic replay, rollback, new process, message or turn occurs. One in-flight tree action excludes concurrent starts, model saves and closure. Existing tree policy derives from the owner's current setting until explicitly changed.

First opening a known agent immediately displays its target identity and stable Composer, while only the transcript loads. Draft typing is available; Send, Stop, title and settings mutations wait for authoritative detail. Arrival preserves Composer focus, caret and draft. Failure retains the frame with localized Retry. Cached history and reading positions retain their existing bounded browser-memory contract.

The native recent window and device-local pending messages are readable immediately. On a first visit, server recovery records wait for the first HTTP history check, with a localized loading status beside the recent content. Successful native identity matches retire temporary recovery rows; a failed read keeps unresolved records accessible and permits Retry without inferring that the Peer is offline or replaying submissions. Cached native reading remains immediate.

A new Codex session saves its existing Grove title with native `thread/name/set` before creation succeeds. This persists an unsent paginated thread for passive reading after restart. Rejected, disconnected or timed-out saves fail creation without automatically repeating creation or naming; an unknown save may have persisted native state. Restoring an existing thread preserves its native title. Passive history never names, resumes or sends to repair missing history.

A freshly started native thread is known empty until a send is attempted or a native event arrives. During that interval Grove serves an empty reading page without invoking native item listing, so a new unsent session shows its first-input state. This knowledge ends on release or connection replacement; resumed threads and uncertain sends still use normal native reads and expose genuine errors with Retry.

## Independent connections and recovery

The browser reconnects to the same local instance and retains its last-known read-only cache. Disconnection disables writes until the connection recovers. Standard WebSocket Ping/Pong checks the browser connection; the browser also uses a lightweight identity probe because it has no Ping API. Business request deadlines reject individual requests without closing the socket. Quota and model queries do not act as heartbeats.

Reconnection verifies identity and obtains a fresh authoritative snapshot. Each browser/connection independently selects its visible detail. Closing an observation connection does not interrupt execution.

Each message has an immutable operation ID and content envelope. Public receipts are **accepted** (the existing native start/steer confirmation) or **rejected** (definitely not received). Lookup on the local instance returns `null` when still processing, native admission is unknown or no record exists. Null supplies no rejection, recovery permission or replay. Browser-local results are **pending / accepted / rejected**; the existing single operation journal and backend execution states keep their internal encoding, without storage migration or a second decoder.

If opening or resuming the original native thread fails before an input is sent, that new submission is rejected with the actual error and **Restore to draft**. For example, an older unsaved empty thread may have no native rollout to resume. Grove does not replace that thread or pretend it accepted the input. Failures after a native send attempt remain unknown unless receipt or matching native input proves an outcome; previously uncertain submissions are not reclassified or replayed. Unsupported history reads remain separate, actionable reading errors.

## Native runtime ownership

Each execution host lazily starts **one Grove-owned managed Codex app-server** for all of its Orc/Worker handles, history/model/skill/usage catalog reads and title threads. Concurrent opens share the same connecting client. Grove uses the existing explicit executable path, environment and bootstrap; it does not attach to, start or manage a system daemon.

Thread start captures each agent’s model/effort/service tier alongside cwd, role instructions and private MCP token. Resume keeps the native thread’s saved model/effort/service tier; Grove reconciles its display cache at startup and when selecting detail. Native notifications are filtered by thread ID. Native synchronous requests without an owned thread are rejected; Grove’s async question/MCP flow remains the supported interaction and no approval/tool consumption is fabricated. Stop targets only its observed thread/turn. Closing an agent aborts its title task and unsubscribes only its native thread, leaving Codex’s native unload lifecycle and other threads intact. Tree/report/question closure guards and native writer locks remain in force.

A successful native resume establishes the execution handle with any cursor returned by native; a missing cursor does not require a history probe before sending. Authorized history reads synchronize their own content and cursors separately, retaining errors and Retry without tearing down a successfully resumed handle.

A shared process disconnect affects its open agents together. They show interrupted/unknown results; the next explicit operation reconnects the managed client and resumes the original thread. Unknown submitted inputs are not replayed. Closing a browser releases only observation. Shutting down Grove closes its managed client. Isolated tests observe one process for two concurrent agents plus catalog/title work, versus the previous per-agent processes and separate catalog process. This is process-count evidence; no measured memory or CPU saving is claimed.

## Codex and Pi sessions

Spec **#4298** adds independent execution-backend selection for Orc, future Worker defaults, every Reviewer profile and Researcher. New session and Settings let you choose Codex/Pi first, then a model from that backend. Pi selection includes its provider; provider, model and backend remain separate identities even when names match. Existing sessions keep their backend. A model change applies to the next new run; the current run retains its captured selection. Missing models, credentials, disabled image reading (`images.blockImages`) or unsupported images fail explicitly without switching engines or dropping attachments.

Pi tool reads and submitted images use Durable's public Photon processor, with the selected model's image width/height/base64-byte limits and SDK defaults for unspecified limits. Grove retains original attachments and fingerprints original input before model-dependent preparation; a failed preparation rejects the whole input. Working/stopping, unknown terminal outcomes, unanswered/delegated questions, undelivered reports, unconfirmed deliveries and in-flight starts/settings/child operations refuse the entire tree before any release. Eligible idle children or children with confirmed terminal failure are released first, then Orc. A native release failure retains Orc and remaining members for explicit retry; confirmed child closures remain closed. For a Codex session without a cached handle, Close does not resume historical content: it confirms that the thread is absent from the owned app-server and requires native `notLoaded` confirmation. A missing rollout alone never confirms release; a still-loaded thread without a handle remains blocked for inspection. Concurrent tree mutations are refused during release, while other trees stay usable. History and owner identities remain; restart/disconnection never replay an unknown Close. Resume continues to reopen only Orc: closed children stay closed and are unavailable through role list/read. Success removes the tree and shows a three-second toast; refusal explains the guard beside the row or current detail. **Zero Workers is only a current count**; the application does not infer task completion or suggest closing from it.

The upper-right weekly inner ring and adjacent percentage both show **quota used** from the local instance. The current instance supplies quota and model catalogues. The instance validates model, effort and Fast capabilities when creating or updating sessions. The quota reader chooses the official window with `windowDurationMins: 10080`, regardless of primary/secondary position. Remaining is clamped `100 - usedPercent`; missing data is a dash until a valid instance cache exists. Quota buckets are never summed. Blue is normal; amber means remaining quota is 20% or less (used quota is at least 80%). The popover shows account identity, instance source and supplied reset time. All local trees share one origin-scoped instance quota cache, including on mobile. Requests poll every 60 seconds and manual refresh remains available; overlapping instance requests are shared. Failed refreshes, missing numeric values and browser disconnection retain the last valid percentage and metadata through remounts and reloads. Reset time appears only when supplied.

## Workspace storage

`server/schema.ts` defines the typed SQLite schema using Drizzle ORM's Bun adapter. Five business tables separate session identity and current state (`sessions`), captured prompts/profile/default settings (`session_config`), immutable operation envelopes and current outcomes (`deliveries`), original questions and confirmed answers (`questions`), and ordered per-operation question/answer associations (`delivery_questions`). Operation IDs are scoped to the receiving session. Original array order is stored independently of timestamps. Association identity is `(session_id, operation_id, position)`: repeated question IDs in one legal delegated envelope retain their original sequence. A NULL associated answer falls back to the operation's original text; an explicit empty string remains empty.

Small JSON objects have named TypeScript contracts: project alias/name/path snapshots, current execution settings, durable recovery guards, current role task, diagnostics, captured configuration, and report target snapshots. Current Reviewer targets can change; earlier report targets remain captured. Private MCP tokens stay durable and are omitted from public projections. Image files and native transcripts remain under their existing authorities. User-handoff candidates and handoff/final-failure notification identities remain instance-local memory and are projected in snapshots; they are not a durable notification ledger. Workspace/reading revisions, cursors, online timing, branch projections and message bodies are not persisted in this database.

Before accepting requests, startup runs the committed `drizzle/` SQL with Drizzle's Bun migrator. Its `__drizzle_migrations` log is the sole schema version record. The first migration creates the tables, converts the previous single-row JSON using SQLite JSON functions, and removes `workspace` in the same transaction as its success record. Failure rolls back business data and the success record and refuses startup; the old data remains available for a repaired retry. An empty migration log table may remain after failure because Drizzle creates that container before BEGIN. Unknown migration hashes/timestamps refuse startup. There is no dynamic schema diff, dual write, or old-version reader. Interrupted turns and unconfirmed admissions reconcile without automatically resending input or replaying native work.

From the `flickgrove` workspace, edit `server/schema.ts`, run `bunx drizzle-kit generate --name=<change>`, and review the generated SQL and snapshot before committing. Run the same command again to check that the schema produces no additional migration. Keep one-time data conversion SQL in its explicit reviewed migration. Normal queries use the typed SQL builder; raw SQL is limited to migration/startup metadata and test diagnostics. The application runs from this checkout (`bun server/main.ts`); ship the `drizzle/` directory beside the server source when packaging it.

Only open aggregates load at startup. Closed histories load by identity/thread on demand and rejoin active memory only after explicit restoration. The existing mutable Workspace observes durable entity changes in place and queues only those session/config/delivery/question rows for its next transaction. A message event trims only its own memory window (100 items / 256 KiB); it does not diff, serialize or rewrite cold history or the active operation ledger. Admission persists before native send; confirmation and its question answers commit together before publication. A failed write prevents admission/publication. Active aggregate reads then fail closed so uncommitted in-memory confirmations cannot escape through detail/recovery/question APIs; detached committed cold history remains readable. Delayed title callbacks require the same current aggregate and native handle before changing durable state.

Browsers retain their device reading cache. Opening without reading content shows the existing conversation spinner until native history succeeds; failure or a 15-second read timeout ends loading and offers Retry. Existing reading remains visible across empty server-memory publications, reconnects, failed reads and reload. A successful empty native conversation settles normally. Reconnection advances the reading entry’s in-memory generation independently of server revision reuse. In-flight responses/errors from the preceding generation cannot publish content or a synchronized revision; once they settle the current generation fetches again. Native item/client identities merge arrivals and prevent duplicate report cards. Failed submission deletion/retry checks native history as well as the durable journal, so memory eviction cannot weaken acceptance guards. History preview performs reads without resuming a native writer.

Validation uses test-owned SQLite databases, homes/configuration, FakeRuntime, strict native wire and isolated Peer/Chord/browser fixtures. `bun test server/workspace-store.test.ts` exercises the real Bun migrator, complete durable roundtrips, rollback/refusal, cold-row isolation, long ledgers and admission failure. The isolated scale comparison and HTML review are local scratch artifacts, not deployed data. These measurements establish removal of the cumulative save overhead; they do not establish the sole cause of the original Mac disconnection or verify live deployment.
